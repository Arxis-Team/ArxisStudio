# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Оболочка, из которой всё остальное приходит плагинами: в самой студии нет ни одной панели и ни
одного формата документа — она умеет зоны, вкладки, меню, статус-бар и один контракт
расширяемости. Дизайнер форм, дерево решения и запуск проекта в репозитории были и сняты со
сборки в этапе 17: контракт проверялся на коде, которому он был не нужен. Дерево вернулось первым —
окном проекта, встроенным модулем на том же контракте; дизайнер и запуск вернутся плагинами.

Три документа, и они не взаимозаменяемы. [README.md](README.md) — что работает сегодня.
[docs/plan.md](docs/plan.md) — **журнал сделанного, а не опись текущего состояния**: 257 записей,
принятые решения, формат манифеста (приложение A). [docs/design-system.md](docs/design-system.md) —
дизайн-система: роли цвета и пороги контраста, сетка и плотность, типографика, иконки, поведение
контролов и цели редизайна по вехам; числа берутся оттуда, а не придумываются. Мокапа и
дизайн-проекта больше нет, и сверять с ними нечего: тесты темы проверяют правила — пороги,
кратность, наличие состояний, — а не переписанные значения.

## Команды

```bash
git submodule update --init external/ArxisStudio.Controls external/ArxisStudio.Icons external/ArxisStudio.Themes.Arxis external/ArxisStudio.Fonts.Cascadia external/ArxisStudio.ProjectSystem
```

```bash
dotnet build ArxisStudio.slnx
```

```bash
dotnet run --project src/ArxisStudio
```

Это для запуска руками, из своего терминала. Запуск для проверки — отдельным разделом ниже: там
студия должна пережить команду, которая её подняла, и `dotnet run` для этого не годится.

```bash
dotnet test tests/ArxisStudio.Tests
```

Один тест или один класс:

```bash
dotnet test tests/ArxisStudio.Tests --filter 'FullyQualifiedName~StudioDockTests.A_panel_comes_back_exactly_where_it_stood'
```

Плагин собирается обычным `dotnet build` — таргет упаковки приезжает вместе с SDK и раскладывает
выход в формат каталога сам, в `package/` рядом с проектом (папка в `.gitignore`). Архив и
отладочная установка — по просьбе:

```bash
dotnet build src/Plugins/Arxis.HelloPlugin -p:AxPluginPack=true
```

```bash
dotnet build src/Plugins/Arxis.HelloPlugin -p:AxPluginDeploy=true
```

Второе кладёт плагин прямо в `%AppData%/ArxisStudio/plugins/<id>`, мимо менеджера. Закрывать
студию для этого не нужно: она держит теневую копию, а не сами файлы, — выложите сборку и
нажмите «Плагины → Перезагрузить».

Отдельного линтера нет: `TreatWarningsAsErrors` включён на всё решение, и сборка идёт с нулём
предупреждений. Это не случайность и не то, что можно «пока оставить». XML-комментарии проверяет
она же: файл документации генерируется у каждого проекта под `src`, потому что без него
компилятор комментарии не разбирает вовсе, и незакрытый тег или ссылка на переименованный метод
живут незамеченными. У приложения файл остаётся в `obj` — у корня выхода лежит только студия.
Новому проекту генерацию включают сразу; забытое называет `DocumentationBuildTests`.

Данные пользователя — `%AppData%/ArxisStudio`: `settings.json`, `layout.json`,
`recent-projects.json`, `keymap.json` (его пишет только человек), `lang/`, `plugins/` (и `plugins/.disabled.json`, где помнится, кого
выключили). Теневые копии — в `%TEMP%/arxis-plugin-shadow` и `arxis-contract-shadow`, чистятся
при первом обращении за сеанс. Локальная история — в машинной папке,
`%LocalAppData%/ArxisStudio/LocalHistory`: она большая и привязана к машине. Переменная
`ARXIS_LOCAL_HISTORY` переносит её, а `0` выключает — так живёт процесс тестов (`TestLocalHistory`),
и тест истории называет свою временную папку прямо.

## Проверка на живой студии

**Проверяя работу, студию запускают и управляют ею через MCP — это ожидаемый способ, а не
исключение, и спрашивать разрешения на него не нужно.** Тесты закрепляют поведение, а живая
студия отвечает на то, чего в них не видно: встала ли панель в зону, что показывает окно после
щелчка, не обрезалось ли в светлой теме. `F12` открывает те же инструменты руками —
[docs/devtools.md](docs/devtools.md).

Запускать **собранный exe**, а не `dotnet run`: порождающий процесс умирает вместе с командой и
уносит студию с собой. Перед пересборкой студию закрывают — теневая копия есть у плагинов, а не
у неё самой, и запущенная студия держит свои сборки: пересборка падает с `MSB3027`/`MSB3021`,
называя процесс и его pid. Предупреждения, которыми такой прогон обрастает, к коду отношения не
имеют и уходят вместе с блокировкой.

```bash
dotnet build ArxisStudio.slnx && powershell -c "Start-Process 'src\ArxisStudio\bin\Debug\net10.0\ArxisStudio.exe'"
```

Историю студии, поднятой для проверки, уводят во временную папку — `$env:ARXIS_LOCAL_HISTORY` в
той же команде PowerShell перед `Start-Process`: служба проектов открывает историю при подъёме
модуля, ещё на Welcome, и без переменной живая проверка писала бы в историю человека.

Конечная точка поднимается сразу при старте, ждать открытия окна инструментов не надо. Порты
заняты так: **5171** — студия, **5172** — витрина контролов, **5173** — витрина иконок. Обе
витрины живут в подмодулях, в `ArxisStudio.slnx` их нет и запускаются они своими решениями
(`dotnet run --project external/ArxisStudio.Controls/samples/Controls.Gallery`). Вторая студия
рядом с первой — `ARXIS_SINGLE_INSTANCE=0` и `ARXIS_DEVTOOLS_MCP_PORT=5199`; остальные переменные в
[docs/devtools.md](docs/devtools.md).

**Студия одна на папку данных.** Вторая, запущенная над той же `%AppData%/ArxisStudio`, не
поднимается, а отдаёт первой свои аргументы и уходит: двойной щелчок по решению при открытой
студии открывает его в ней, щелчок по значку выводит её вперёд. Поэтому проверка, которой нужна
вторая студия рядом с первой, снимает это правило переменной `ARXIS_SINGLE_INSTANCE=0` — иначе
вторая молча отдаст управление первой, и `list_windows` на новом порту не ответит ничем. Две
студии над одной папкой спорят за её файлы: раскладку запишет та, что закроется последней.

Клиент MCP сессии подключается один раз, на старте. Если студия поднялась позже, инструменты в
этой сессии останутся недоступными до переподключения — но с конечной точкой можно говорить и
напрямую, обычным JSON-RPC по HTTP. Клиента хватает вот такого:

```python
import json, urllib.request
def call(name, args=None, port=5171):
    body = json.dumps({"jsonrpc":"2.0","id":9,"method":"tools/call",
                       "params":{"name":name,"arguments":args or {}}}, ensure_ascii=True).encode("ascii")
    req = urllib.request.Request(f"http://127.0.0.1:{port}/", data=body,
        headers={"Content-Type":"application/json","Accept":"application/json, text/event-stream"})
    return json.loads(urllib.request.urlopen(req, timeout=40).read().decode("utf-8"))
```

`ensure_ascii=True` здесь обязателен: русский запрос, посланный через `curl` из шелла, доезжает
до студии искажённым, и `find_elements` отвечает «ничего не найдено» на текст, который в окне
есть. Экранирование в `\uXXXX` снимает вопрос целиком.

Порядок работы задают сами инструменты: `list_windows` первым — всё остальное берёт `elementId`,
и живут эти номера, пока жив элемент. Дальше `find_elements` превращает видимый текст в номер,
`click` его нажимает, `screenshot` показывает, что вышло, `get_problems` со `scan: true`
подметает дерево на сломанные привязки, `run_variants` перечитывает студию в светлой теме, при
двойном тексте и в узком окне.

Пять мест, где легко обмануться:

- **Неизвестный параметр не отвергается, а подменяется умолчанием.** Поле называется
  `elementId`; передав `id`, вы получите не ошибку, а дерево или снимок «главного окна» — то есть
  `desktop.MainWindow`, которым после перехода в студию остаётся уже скрытое окно Welcome.
- **«Nothing in the application handled it» — про флаг `e.Handled`, а не про то, что обработчик
  не вызвался.** Обработчики студии его чаще всего не ставят, так что судить надо по
  последствию: позвать `list_windows` или `screenshot` и посмотреть, что стало.
- **Точка отвечает раньше, чем появляется окно.** Инструменты подключаются в `App.Initialize`, а
  под заставкой ещё поднимаются модули и плагины, поэтому первый `list_windows` вполне может
  ответить `SplashWindow` — и поиск по видимому тексту тогда не найдёт ничего. Дождитесь
  `WelcomeWindow`, а не просто открытого порта.
- **Студия открывается на Welcome.** До главного окна её доводят две двери: кнопка «Каркас
  студии» — в пустой каркас — и строка недавнего проекта, открывающая его. Панелей, полосы и
  раскладки до этого нет вовсе. Названный в командной строке проект Welcome пропускает вовсе.
- **`run_variants` оставляет активным главное окно.** Открытый модальный диалог после него уже
  не в фокусе, и `press_key` без `elementId` уходит в главное окно — в ту строку, где стоял
  человек. Кнопку диалога после вариантов жмут `click` по её номеру.

Запущенное за собой закрывают по номеру процесса: `Start-Process -PassThru` его отдаёт, а
`Stop-Process -Id <номер> -Force` закрывает. По имени закрывать нельзя — рядом может работать
студия человека, со своей историей в `%LocalAppData%`, и её эта папка: проверка её не чистит.
Следов в репозитории проверка не оставляет — трогается только `%AppData%/ArxisStudio`, и то
обычной работой студии: раскладка пишется по таймеру во время сеанса, а `Farewell` дописывает
остаток при штатном закрытии, которое `-Force` как раз пропускает.

| [ArxisStudio.Sdk.Analyzers](src/ArxisStudio.Sdk.Analyzers) | ARX0001–ARX0014, едут вместе с SDK | Roslyn |

| [ArxisStudio.Extensibility](src/ArxisStudio.Extensibility) | хост плагинов: контексты загрузки, граф, контракты, шов сбоев | Sdk, Shell |
| [ArxisStudio.LocalHistory](src/ArxisStudio.LocalHistory) | локальная история: содержимое по адресу, журнал по дням, известное состояние, срок | ничего, кроме платформы |
| [ArxisStudio.Projects.Contracts](src/Modules/ArxisStudio.Projects.Contracts) | контракт службы проектов: состояние, перемены, дорога из контекста | Sdk, ядро ProjectSystem — и ни одного движка |
| [ArxisStudio](src/ArxisStudio) | приложение и вся склейка | всё |

Направление держит сборка, а не уговор. Таргет `AxDockingBoundary` в
[ArxisStudio.Docking.csproj](src/ArxisStudio.Docking/ArxisStudio.Docking.csproj) валит сборку с
`AXD1001`, если у движка объявлена ссылка на Sdk, Shell или Extensibility, а `DockingBoundaryTests`
смотрит на готовую сборку. Причина в самом сообщении: раскладка переживает выключение плагина и
уезжает в файл, поэтому узел дерева, удержавший объект плагина, навсегда оставит в памяти его
контекст загрузки. Движку нужны идентификаторы, живые контролы держит студия.

У локальной истории граница строже: ссылок нет никаких, и `AXH1001` валит сборку на первой же,
а `LocalHistoryBoundaryTests` смотрит на готовую. Журнал и хранилище переживают студию и читаются
её следующей версией — их формат не должен зависеть ни от интерфейса, ни от движка, ни от модели
проектов. Что считать файлом проекта и когда снимать, решает служба проектов: библиотека хранит
то, что ей дали. Библиотеку везёт модуль «Проекты» в своём `bin`, тесты называют её так же, как
движки, — только для компиляции.

У SDK то же правило словами: реализации студии в нём быть не должно. Исключение одно и осознанное —
библиотека контролов: интерфейс плагина строится только на `Ax*`, и ссылаться на неё плагин обязан
в любом случае.

## Две доставки, один контракт

Внешний плагин — папка с `plugin.json` и сборкой; та же папка в zip — это `.axplugin`. Живёт в
своём выгружаемом `AssemblyLoadContext`, грузится из теневой копии, перезагружается на ходу.
Встроенный модуль — такая же папка с `module.json` и `bin/`, только приезжает она со студией,
живёт в основном контексте и отдельно не выгружается. **Код между режимами переносится без правок**, и в репозитории есть образец каждого:
`src/Plugins/Arxis.HelloPlugin` и `src/Modules/ArxisStudio.Modules.Sample`. Рабочих модулей четыре, а не образцов —
`src/Modules/ArxisStudio.Modules.Terminal`, `src/Modules/ArxisStudio.Modules.Console`,
`src/Modules/ArxisStudio.Modules.Projects` — служба без единой панели, отдающая соседям контракт
`ArxisStudio.Projects.Contracts` (объявлен в `provides.contracts`), — и
`src/Modules/ArxisStudio.Modules.Project`, окно проекта: первый потребитель этого контракта, и берёт
он его так же, как взял бы плагин. Служб в контракте пять, и разведены они
по тому, чем занят берущий: модель — `context.Projects()`, сборка — `context.Build()`, пакеты —
`context.Packages()`, файлы — `context.Files()`, история — `context.History()`. Файлы решения правят
только через службу файлов: она переписывает ссылки файла проекта, перечитывает модель и пишет
действие в локальную историю, а правка мимо неё расходится со снимком. Отмена и возврат из истории
ходят той же дорогой (`FilesService.EditAsync`) — иначе разошлись бы со снимком так же. Автору плагина об этом написано в [docs/projects.md](docs/projects.md), и
примеры оттуда компилируются тестом: правка контракта, их сломавшая, падает там. Имена близки, и
путать их нельзя: `arxis.projects` — служба, `arxis.project` — окно; сравнения в коде точные.

Отличий ровно два: список модулей объявлен в самой студии
([`StudioModules.Assemblies`](src/ArxisStudio/Services/StudioModules.cs) — сюда добавляют новый
модуль, а в [ArxisStudio.csproj](src/ArxisStudio/ArxisStudio.csproj) — ссылку на него с пометками
`StudioModule="true" Private="false" ExcludeAssets="runtime"`), и выгрузить модуль отдельно нельзя.

**У корня выхода — только сама студия.** Платформа лежит в `lib/`, у корня остаются exe, сборка
студии и два файла среды, а у каждого модуля **своя папка в `modules/`, формой как у установленного
плагина**: манифест в корне, сборки в `bin/`.

```
modules/arxis.terminal/module.json
modules/arxis.terminal/bin/{ArxisStudio.Modules.Terminal,Porta.Pty,XTerm.NET}.dll
```

Имя папки — идентификатор из манифеста; читает его сам модуль, а не студия. Правила раскладки —
[build/ArxisStudio.Library.targets](src/ArxisStudio/build/ArxisStudio.Library.targets) и
[build/ArxisStudio.Modules.targets](src/ArxisStudio/build/ArxisStudio.Modules.targets); состав модуль
отдаёт сам (цель `StudioModuleFiles` в
[src/Modules/Directory.Build.targets](src/Modules/Directory.Build.targets)), а дорогу к обеим папкам
основной контекст загрузки получает от
[`StudioAssemblyFolder`](src/ArxisStudio/Services/StudioAssemblyFolder.cs): платформу он ищет в самой
папке, модули — в `bin` каждого.

**Один файл — один модуль.** Модули живут в одном основном контексте загрузки, где имя грузится
ровно один раз, и две папки с одноимённой сборкой дали бы две копии на диске и одну работающую.
`AXL1002` валит сборку, называя файл и всех его владельцев; общей сборке место в `lib/` — её проект
называют прямо в `ArxisStudio.csproj`, — а чужой контракт подключают `Private="false"
ExcludeAssets="runtime"`: возит его владелец. Идентификатор, который не прочитался из манифеста,
называет `AXL1003`.

**В `Main` нет ничего, кроме двух строк дороги и вызова `Start`**, и это условие запуска, а не стиль:
JIT компилирует метод целиком до первой его строки, и тип из `lib`, названный в точке входа, роняет
студию раньше, чем встанут резолверы. Правило закреплено тестом. Нативные библиотеки пакетов
остаются в `runtimes/` у корня. Транзитивные ссылки на проекты у приложения выключены, поэтому
проект, нужный самой студии, в её csproj называют прямо — иначе он окажется только в `modules/`. За
раскладкой смотрит `StudioLayoutTests` на собранном выходе. Папка встроенного модуля — та, что над
его `bin/`, и контракт он объявляет от неё же (`bin/…`), слово в слово как плагин.

Словари у модуля свои, в его `lang/`, и дорога к ним та же, что у плагина: чужих ключей — ни
студии, ни соседа — в словаре расширения не видно. Ключи студии внутренние, и переименование одного
не должно менять текст в чужой панели; модуль от этого правила не освобождён, и тем он и
переносится во внешний плагин перекладыванием папки — вместе со строками, а не отдельно от них.
Прежде словарём модулю служили словари студии, и переезд был неполным (записи 231–233).

Меню, кнопки полосы и вкладки панелей студия строит **по манифесту, не загружая сборку**: кнопка
спящего плагина стоит на месте и будит его щелчком. Поэтому `activation` (`onStartup`,
`onCommand:`, `onFileType:`, `onToolWindow:`) — не оптимизация, а часть контракта. Спящий — такой
же житель студии, как поднятый: выключая его, снимают кнопки, сочетания и запись среди ждущих
(`PluginHost.Withdraw`), иначе первое его событие поднимет выключенного. Сочетания манифеста
заявляются один раз на жизнь хозяина — на старте и после каскада, а не до него: уход прежней копии
стирает всё, что на неё записано.

Общие сборки перечислены в `PluginLoadContext.IsShared`: Avalonia, `ArxisStudio.Sdk`,
`ArxisStudio.Controls`, `ArxisStudio.Icons` — семейством, то есть именем целиком или с точкой за
ним, а не по первым буквам: чужая `AvaloniaEdit` остаётся своей у плагина, — и точным именем
`ArxisStudio.ProjectSystem`, ядро модели проектов: снимки решения видят все плагины, а его движки (`.MSBuild`, `.NuGet`) общими не
становятся — их держит служба проектов. Копия любой общей сборки рядом с плагином стала бы вторым
экземпляром того же типа, и приведение упало бы. Поверхности ядра и контракта службы проектов закреплены в
`tests/ArxisStudio.Tests/Surfaces`: сдвиг указателя или правка контракта, их поменявшие, падают там, а не у автора плагина. Контрактные сборки (`provides.contracts`) грузятся
в основной контекст один раз и **не выгружаются**: их обновление честно просит перезапуск, а
[`PluginContracts`](src/ArxisStudio.Extensibility/PluginContracts.cs) это говорит вместо того,
чтобы молча держать прежнюю копию.

**Разметка плагина перезагружается на ходу — с `x:Class` и без, и держит это выгрузка, а не удача.**
Свойство Avalonia кэширует метаданные для каждого типа, у которого их спросило оформление, словарём
с сильным ключом, и тип-контрол плагина, побывавший на экране, не давал контексту выгрузиться.
[`PluginLoadContext.Release`](src/ArxisStudio.Extensibility/PluginHost.cs) снимает эти типы открытым
`AvaloniaPropertyRegistry.UnregisterByModule` — рядом со сбросом кэша загрузчика ресурсов, и новую
уборку перед выгрузкой ставят туда же. Замер, дорога без `x:Class` и чем она платит —
[docs/plugin-markup.md](docs/plugin-markup.md).

## Что нельзя двигать

`AssemblyVersion` прибит на `1.0.0.0` — **навсегда**. Плагин собирается против `ArxisStudio.Sdk` и
запоминает его имя вместе с версией; сдвиг ломает связывание у каждого уже установленного плагина.
Это проверено дорогой ценой и записано в [Directory.Build.props](Directory.Build.props). Меняются
`ArxisRelease` и `Version` — то, что версией называют люди; совместимость плагинов мерится
`sdk.min` в манифесте против `StudioSdk.Version`.

`StudioSdk.Version` (сейчас `7.4`) двигают, когда меняется контракт, и минор — когда добавляется.
`Satisfies` сравнивает мажор и минор, поэтому снятое обещание — это новый мажор, а не «оно и так
не использовалось».

Обещание — не только SDK. Набор контролов, иконки и ядро модели проектов плагин видит общими, и их
поверхность записана в `tests/ArxisStudio.Tests/Surfaces` вместе с номером, при котором её
записали. Разошлась — тест требует сдвига номера (добавленное — минор, снятое — мажор) и только
после сдвига отдаёт новую запись: перенести поверхность мимо номера нечем.

## Правила, которые нарушаются молча

**Строка студии живёт в трёх файлах.** `Localization/Strings/en.json`, `ru.json` и
`templates/Arxis.Language/lang/xx.json` — в шаблоне перевода ровно те же ключи, и это закреплено
`LanguageTemplateTests`. Забыть третий значит выдать переводчику неполный шаблон.

**Словарь расширения называется кодом языка** — `lang/en.json`, `lang/ru.json`, `lang/de.json`,
той же формой, что у самой студии. Английский особый: его читают, когда файла текущего языка нет,
и потому он есть у каждого расширения. Языки одного расширения описывают одни ключи, а общую ветку
меню (`%menu.tools%`) все называют одним словом в каждом языке: ветки сходятся по переведённому
тексту, и расхождение дало бы два раздела, одинаковых с виду. Оба правила держит
`ExtensionStringKeysTests`. Расширение, собранное до SDK 7.0, студия поднимает — прежний старший
номер `Satisfies` пропускает, — но его `lang/strings.json` не читает, и подписи становятся
`!ключами!`; причину называет журнал. Увидев ключи, смотрят туда, а свой пример переустанавливают
`-p:AxPluginDeploy=true`.

**`%ключ%` в манифесте берётся из словаря**, и `ARX0002` говорит при сборке, если ключа нет: у
плагина и у модуля смотрит `lang/en.json` в его папке. Без анализатора об
этом сказала бы студия, но в журнал и уже у пользователя. Словарь, который студия не прочтёт,
называет `ARX0012` — только помеченный сборкой ролью `AxStrings` (`default` или `translation`).
Метит их сборка сама и одинаково: плагину — таргет SDK, модулю — общий
[src/Modules/Directory.Build.targets](src/Modules/Directory.Build.targets), — так что новый модуль
приходит с проверкой, а не забывает её подключить.

**Путь из манифеста остаётся в папке плагина.** Всё, что манифест называет путём, — `entry`,
`icon`, контракт, словарь пакета — и идентификатор, который становится именем папки, проходит через
[`PluginPaths`](src/ArxisStudio.Extensibility/PluginPaths.cs). `Path.Combine` здесь не защита:
корневой второй аргумент он возвращает как есть, и `"id": ".."` при установке с заменой стирал папку
данных студии. Новое поле манифеста с путём читают через `Inside`, а не мимо него.

**Интерфейс строится на `Ax*`, а не на голых виджетах Avalonia.** Панели раскладки, рамки, текст и
фигуры — можно: своего оформления они не несут. Правило проверяется `ARX0001` в коде — созданием и
наследованием: пустой наследник виджета обходил запрет, — и `ARX0006` в разметке; оба называют
замену, а где её нет — говорят и об этом. Анализатор через
`ProjectReference` не передаётся, поэтому каждый модуль и плагин подключает его строкой в своём
csproj — при заведении нового не забудьте.

**Панель прощается перед выгрузкой.** `ToolWindow.Release()` зовётся прежде, чем её сборку
выгрузят: за панелью могут стоять процессы, потоки и подписки, и отпустить их может только она.
То же у `ToolBarItem`. Идёт прощание своей дорогой шва — `PluginGuard.Farewell`, а не рабочей:
рабочая отказывает отключённому за сбои, а прощаться надо как раз с ним. Перезапуск упавшей панели
из заглушки прощается с прежним экземпляром раньше, чем строит новый.

**Значение цвета или размера объявляется в теме и больше нигде** — ни в шаблонах, ни в разметке,
ни в коде панелей. Это правило подмодуля `Themes.Arxis`, но нарушается оно здесь. У расширений его
держит сборка — `ARX0008`–`ARX0010` называют ключ вместо числа, договор описан в
[docs/plugin-markup.md](docs/plugin-markup.md), — а у самой студии храповики в обоих репозиториях:
`LiteralSpacingTests` считает отступы в разметке и в коде, `LiteralRadiusTests` — скругления,
`LiteralSizeTests` — длины, толщины и разрядку. Все они дошли до нуля в вехе метрик и работают
теперь запретом, а исключения названы правилом, а не списком: поправка меньше двух пикселей — не
зазор, размер окна в его открывающем теге — не вёрстка, картинка релиза заставки — рисунок, ширина
канвы плагина — дело плагина. Ключ темы, названный строкой в коде студии, модулей, плагинов,
шаблона, контролов и значков, сверяет с темой `CodeResourceKeysTests`, а в разметке —
`MarkupResourceKeysTests`: опечатка в ключе не валит ни сборку, ни показ. У расширений ту же
опечатку при сборке называет `ARX0009` вместе с похожим ключом; словари темы вшиты в анализатор все,
звёздочкой, и что он знает каждый ключ, названный студией, держит `ThemeValueAnalyzerTests`. Размер значка — `IconPixelTests`, тоже запретом, и не ради порядка: набор нарисован в
клетке 16, и `AxIcon` сводит обводку к целым пикселям только там, где клетка в них ложится, а 18 или
20 точек не ложатся ни при каком обычном масштабе. Растянуть значок можно одним способом —
лестницей плитки окна проекта, 32…128 шагом 16: ключом её ступени у темы или ступенью, которую
колонка поставила списку (`TileMetrics.Glyph`). На плитке стоит только силуэт набора из прямых, и
где единица сетки не целая, `AxIcon` сажает его вершины на пиксели сам; тест мерит кадром каждую
ступень на каждом масштабе. Другой ключ на размере значка тест называет так же, как число.

**Один адрес разметки на все библиотеки студии** —
`https://github.com/Arxis-Team/ArxisStudio`, объявлен `XmlnsDefinition` в каждой из них. Действует
только для сборок, на которые сослался проект, поэтому разграничение выходит само: плагину под ним
открывается ровно то, что ему разрешено. Под адрес Avalonia типы студии не объявляются намеренно —
в разметке расширений родной виджет виден по префиксу. `MarkupNamespaceTests` разбирает разметку на
ходу и проверяет по объявлениям сборок: одно имя под адресом принадлежит одной библиотеке, а
пространство с типами разметки объявлено и не забыто.

**Раскладка пишется отложенно.** [`StudioDock`](src/ArxisStudio/Services/StudioDock.cs) копит
правки и записывает через две секунды: тянут границу — десятки правок за секунду. Тест, который
ждёт файла сразу, должен звать `Flush()`.

**Вид докинга ничего не решает.** `DockView` сообщает о том, что сделал человек (`Dropped`,
`Resized`, `Hiding`, `Closing`, `Chosen`), а дерево правит владелец — `StudioDock`. Так одно и то
же дерево одинаково ведёт себя в главном окне, в оторванном и в тесте, где окна нет вовсе. Дерево
иммутабельно: `DockTree` возвращает новый узел, а не меняет старый. Новое дерево, разошедшееся с
прежним одними долями (`DockTree.Alike`), вид ставит в те же сетки, а не перестраивает окно: на
границе стоит каретка, и перестройка уносила её вместе с разделителем. Границу вид слушает ходом
(`AxSplitter.Moved`), а не концом тяги — стрелками её тоже двигают.

**Сбой плагина не роняет студию.** Вызовы кода уже поднятого плагина идут через
[`PluginGuard`](src/ArxisStudio.Extensibility/PluginGuard.cs); на третьем падении подряд плагин
перестают звать — подряд буквально: прошедший вызов счёт обнуляет, — и отключают один раз, сколько
бы докладов ни пришло следом. Счёт закрыт замком: доклады приходят и из потока финализатора. Панель, упавшая в раскладке, заменяется заглушкой
([`PluginSurface`](src/ArxisStudio.Shell/PluginSurface.cs) ловит исключения в `Measure`/`Arrange`).
Новый вызов чужого кода добавляют через шов, а не мимо него: редакторы документов идут через него
на каждой дороге — постройка, вопрос, открытие, показ, — а закрытие, как всякое прощание,
прощальной дорогой (`FarewellAsync`).

**У команды один хозяин.** Занятую команду реестр другому не отдаёт и говорит об этом в журнал;
своё перезаявить можно, а заявка студии вытесняет чужую. Идентификатору команды плагина нужна его
приставка.

У подъёма шов **свой**, и это не упущение: `Activate` и `Start` зовутся из
[`PluginHost`](src/ArxisStudio.Extensibility/PluginHost.cs) напрямую, потому что считать падения
ещё не поднятого плагина некому и незачем — он просто не поднимется. Роль шва там играет фильтр
`catch`, и поэтому он широкий: ловится всё, кроме нехватки памяти и переполнения стека. Пока он
перечислял беды по именам, неназванная уносила студию целиком — `NullReferenceException` из чужого
`Activate` не был назван. Сужать его обратно нельзя. Внутри шва стоит и конструктор контекста
загрузки — он читает `.deps.json` плагина и бросает на обрезанном, — а сбой на середине подъёма
останавливает тех, кого успел позвать: службы, потом точки входа, включая упавшего.

Запись у плагина в хосте одна — поднятая или с ошибкой: новая попытка прежнюю ошибку вытесняет, а
встроенность спрашивают признаком `IsBuiltIn`, не отсутствием контекста. `PluginHost.Loaded` —
снимок: его читают и не из потока интерфейса.

## Тесты

1670 тестов, headless-UI на `Avalonia.Headless.XUnit`, и пакет завязан на **xunit v3**. Тесту,
которому нужно живое дерево контролов, нужен `[AvaloniaFact]`, а не `[Fact]`: он поднимает
приложение из `TestApp` и загоняет тело в UI-поток. Рисование настоящее (`UseSkia`,
`UseHeadlessDrawing = false`) — заглушка не зовёт декодер картинок и на любой файл отвечает
болванкой нужного размера, так что «значок прочитался» проходило бы и на текстовом файле.

`TestApp` ставит **все три слоя стилей в том же порядке, что `App.axaml`**: ArxisTheme,
ShellStyles, DockingStyles. Порядок решает, кто кого перекроет; без слоя оболочки проверять её
было нечем. Чужой базовой темы под ними нет ни здесь, ни в студии: окно, окно попапа и простые
контейнеры одевает сама тема, и дыра в её покрытии видна сразу — подменить её собой некому.

Тесты, трогающие общее на процесс, идут по одному —
`[Collection(StudioStateCollection.Name)]`. Общего три: `Localizer` один на процесс, выгрузка
контекстов загрузки опирается на сборщик мусора, тоже один, а регистрация MSBuild, которой служба
проектов открывает решения, одна на процесс и насовсем. Остальные классы xUnit пускает
параллельно, и это правильно — очередь заведена ровно для тех, у кого общее состояние.

Имена тестов — английская фраза с подчёркиваниями (`A_pack_made_from_the_template_works`),
сообщения в `Assert` — русские. Проверять надо наблюдаемое поведение, а не внутренние структуры.
`Thread.Sleep` вместо координации не годится: в безголовом режиме время стоит, и у пары жестов
подряд счёт щелчков сбивается — между ними ставят щелчок в стороне, а не паузу.

Внутренности студии открыты тестам через `InternalsVisibleTo` в
[ArxisStudio.csproj](src/ArxisStudio/ArxisStudio.csproj).

## Подмодули

Собираются пять из семи: **Controls** (контролы `Ax*`, lookless), **Icons** (контуры 16×16 и
`AxIcon`), **Themes.Arxis** (палитры, шаблоны, метрики), **Fonts.Cascadia** (шрифт ресурсом) и
**ProjectSystem** — не весь, а ядро модели, провайдер MSBuild и правку пакетов: их держит служба
проектов, а адаптер разметки ждёт своего шага. Шрифт называет не решение, а тема.

Зарегистрированы и не собираются: **Markup** (lossless XAML DOM и round-trip) и **DesignEditor**
(канва; ещё `net8.0` — при интеграции поднимать). Их SHA — запись того API, против которого
работал снятый код; они ждут возвращения дизайнера. В `ArxisStudio.slnx` их нет, и работать с
ними нужно их собственными решениями, они лежат в корне каждого подмодуля. Так же проверяется и
ProjectSystem: студия собирает его исходники, а его тесты гоняет его собственное решение.

**API подмодулей можно менять** — это не замороженные зависимости. Если интеграции нужен новый
или изменённый публичный API, правьте прямо в подмодуле и коммитьте в его репозиторий, соблюдая
его правила: у Markup, ProjectSystem и DesignEditor есть свой `CLAUDE.md`, и внутри их каталогов
он старше этого файла. Указатель подмодуля обновляется в том же коммите студии, что и правка,
которой он понадобился.

## Коммиты

Заголовок — русская фраза о том, что стало, без префикса и без точки: «Рейки по краям окна вместо
сворачивания», «Версия сборки закреплена: плагины ссылаются на неё». Тело — проза: что было не
так, почему решено именно так, на что смотрели у Visual Studio и Rider, что уехало в подмодули.
Последняя строка — счёт: `922 теста, 0 предупреждений. Запись 130 в плане.` Запись в
[docs/plan.md](docs/plan.md) идёт тем же коммитом, что и код.
