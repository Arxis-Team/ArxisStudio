# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Оболочка, из которой всё остальное приходит плагинами: в самой студии нет ни одной панели и ни
одного формата документа — она умеет зоны, вкладки, меню, статус-бар и один контракт
расширяемости. Дизайнер форм, дерево решения и запуск проекта в репозитории были и сняты со
сборки в этапе 17: контракт проверялся на коде, которому он был не нужен. Вернутся плагинами.

Три документа, и они не взаимозаменяемы. [README.md](README.md) — что работает сегодня.
[docs/plan.md](docs/plan.md) — **журнал сделанного, а не опись текущего состояния**: 104 записи,
принятые решения, формат манифеста (приложение A). [docs/design-spec.md](docs/design-spec.md) —
входные данные дизайна: токены, метрики, инвентарь экранов; числа берутся оттуда, а не
придумываются.

## Команды

```bash
git submodule update --init external/ArxisStudio.Controls external/ArxisStudio.Icons external/ArxisStudio.Themes.Arxis external/ArxisStudio.Fonts.Cascadia
```

```bash
dotnet build ArxisStudio.slnx
```

```bash
dotnet run --project src/ArxisStudio
```

Это для запуска руками, из своего терминала. Запуск для проверки — отдельным разделом ниже: там
студия должна пережить команду, которая её подняла, и `dotnet run` для этого не годится.

```bash
dotnet test tests/ArxisStudio.Tests
```

Один тест или один класс:

```bash
dotnet test tests/ArxisStudio.Tests --filter 'FullyQualifiedName~StudioDockTests.A_panel_comes_back_exactly_where_it_stood'
```

Плагин собирается обычным `dotnet build` — таргет упаковки приезжает вместе с SDK и раскладывает
выход в формат каталога сам, в `package/` рядом с проектом (папка в `.gitignore`). Архив и
отладочная установка — по просьбе:

```bash
dotnet build src/Plugins/Arxis.HelloPlugin -p:AxPluginPack=true
```

```bash
dotnet build src/Plugins/Arxis.HelloPlugin -p:AxPluginDeploy=true
```

Второе кладёт плагин прямо в `%AppData%/ArxisStudio/plugins/<id>`, мимо менеджера. Закрывать
студию для этого не нужно: она держит теневую копию, а не сами файлы, — выложите сборку и
нажмите «Плагины → Перезагрузить».

Отдельного линтера нет: `TreatWarningsAsErrors` включён на всё решение, и сборка идёт с нулём
предупреждений. Это не случайность и не то, что можно «пока оставить».

Данные пользователя — `%AppData%/ArxisStudio`: `settings.json`, `layout.json`,
`recent-projects.json`, `lang/`, `plugins/` (и `plugins/.disabled.json`, где помнится, кого
выключили). Теневые копии — в `%TEMP%/arxis-plugin-shadow` и `arxis-contract-shadow`, чистятся
при первом обращении за сеанс.

## Проверка на живой студии

**Проверяя работу, студию запускают и управляют ею через MCP — это ожидаемый способ, а не
исключение, и спрашивать разрешения на него не нужно.** Тесты закрепляют поведение, а живая
студия отвечает на то, чего в них не видно: встала ли панель в зону, что показывает окно после
щелчка, не обрезалось ли в светлой теме. `F12` открывает те же инструменты руками —
[docs/devtools.md](docs/devtools.md).

Запускать **собранный exe**, а не `dotnet run`: порождающий процесс умирает вместе с командой и
уносит студию с собой. Перед пересборкой студию закрывают — теневая копия есть у плагинов, а не
у неё самой, и запущенная студия держит свои сборки: пересборка падает с `MSB3027`/`MSB3021`,
называя процесс и его pid. Предупреждения, которыми такой прогон обрастает, к коду отношения не
имеют и уходят вместе с блокировкой.

```bash
dotnet build ArxisStudio.slnx && powershell -c "Start-Process 'src\ArxisStudio\bin\Debug\net10.0\ArxisStudio.exe'"
```

Конечная точка поднимается сразу при старте, ждать открытия окна инструментов не надо. Порты
заняты так: **5171** — студия, **5172** — витрина контролов, **5173** — витрина иконок. Обе
витрины живут в подмодулях, в `ArxisStudio.slnx` их нет и запускаются они своими решениями
(`dotnet run --project external/ArxisStudio.Controls/samples/Controls.Gallery`). Вторая студия
рядом с первой — `ARXIS_DEVTOOLS_MCP_PORT=5199`; остальные переменные в
[docs/devtools.md](docs/devtools.md).

Клиент MCP сессии подключается один раз, на старте. Если студия поднялась позже, инструменты в
этой сессии останутся недоступными до переподключения — но с конечной точкой можно говорить и
напрямую, обычным JSON-RPC по HTTP. Клиента хватает вот такого:

```python
import json, urllib.request
def call(name, args=None, port=5171):
    body = json.dumps({"jsonrpc":"2.0","id":9,"method":"tools/call",
                       "params":{"name":name,"arguments":args or {}}}, ensure_ascii=True).encode("ascii")
    req = urllib.request.Request(f"http://127.0.0.1:{port}/", data=body,
        headers={"Content-Type":"application/json","Accept":"application/json, text/event-stream"})
    return json.loads(urllib.request.urlopen(req, timeout=40).read().decode("utf-8"))
```

`ensure_ascii=True` здесь обязателен: русский запрос, посланный через `curl` из шелла, доезжает
до студии искажённым, и `find_elements` отвечает «ничего не найдено» на текст, который в окне
есть. Экранирование в `\uXXXX` снимает вопрос целиком.

Порядок работы задают сами инструменты: `list_windows` первым — всё остальное берёт `elementId`,
и живут эти номера, пока жив элемент. Дальше `find_elements` превращает видимый текст в номер,
`click` его нажимает, `screenshot` показывает, что вышло, `get_problems` со `scan: true`
подметает дерево на сломанные привязки, `run_variants` перечитывает студию в светлой теме, при
двойном тексте и в узком окне.

Четыре места, где легко обмануться:

- **Неизвестный параметр не отвергается, а подменяется умолчанием.** Поле называется
  `elementId`; передав `id`, вы получите не ошибку, а дерево или снимок «главного окна» — то есть
  `desktop.MainWindow`, которым после перехода в студию остаётся уже скрытое окно Welcome.
- **«Nothing in the application handled it» — про флаг `e.Handled`, а не про то, что обработчик
  не вызвался.** Обработчики студии его чаще всего не ставят, так что судить надо по
  последствию: позвать `list_windows` или `screenshot` и посмотреть, что стало.
- **Точка отвечает раньше, чем появляется окно.** Инструменты подключаются в `App.Initialize`, а
  под заставкой ещё поднимаются модули и плагины, поэтому первый `list_windows` вполне может
  ответить `SplashWindow` — и поиск по видимому тексту тогда не найдёт ничего. Дождитесь
  `WelcomeWindow`, а не просто открытого порта.
- **Студия открывается на Welcome.** До главного окна её доводит щелчок по «Каркас студии» —
  панелей, полосы и раскладки до этого нет вовсе.

Запущенное за собой закрывают: `Stop-Process -Name ArxisStudio -Force`. Следов в репозитории
проверка не оставляет — трогается только `%AppData%/ArxisStudio`, и то обычной работой студии:
раскладка пишется по таймеру во время сеанса, а `Farewell` дописывает остаток при штатном
закрытии, которое `-Force` как раз пропускает.

## Слои и направление ссылок

| Проект | Роль | Ссылается на |
|---|---|---|
| [ArxisStudio.Sdk](src/ArxisStudio.Sdk) | контракт для плагинов и модель манифеста | Controls, Icons — и ничего из студии |
| [ArxisStudio.Sdk.Analyzers](src/ArxisStudio.Sdk.Analyzers) | ARX0001–ARX0006, едут вместе с SDK | Roslyn |
| [ArxisStudio.Shell](src/ArxisStudio.Shell) | каркас окна, словари, настройки, полоса | Controls, Icons |
| [ArxisStudio.Docking](src/ArxisStudio.Docking) | движок докинга | Controls, Icons |
| [ArxisStudio.Extensibility](src/ArxisStudio.Extensibility) | хост плагинов: контексты загрузки, граф, контракты, шов сбоев | Sdk, Shell |
| [ArxisStudio](src/ArxisStudio) | приложение и вся склейка | всё |

Направление держит сборка, а не уговор. Таргет `AxDockingBoundary` в
[ArxisStudio.Docking.csproj](src/ArxisStudio.Docking/ArxisStudio.Docking.csproj) валит сборку с
`AXD1001`, если у движка объявлена ссылка на Sdk, Shell или Extensibility, а `DockingBoundaryTests`
смотрит на готовую сборку. Причина в самом сообщении: раскладка переживает выключение плагина и
уезжает в файл, поэтому узел дерева, удержавший объект плагина, навсегда оставит в памяти его
контекст загрузки. Движку нужны идентификаторы, живые контролы держит студия.

У SDK то же правило словами: реализации студии в нём быть не должно. Исключение одно и осознанное —
библиотека контролов: интерфейс плагина строится только на `Ax*`, и ссылаться на неё плагин обязан
в любом случае.

## Две доставки, один контракт

Внешний плагин — папка с `plugin.json` и сборкой; та же папка в zip — это `.axplugin`. Живёт в
своём выгружаемом `AssemblyLoadContext`, грузится из теневой копии, перезагружается на ходу.
Встроенный модуль — `module.json` ресурсом внутри сборки, основной контекст, отдельно не
выгружается. **Код между режимами переносится без правок**, и в репозитории есть образец каждого:
`src/Plugins/Arxis.HelloPlugin` и `src/Modules/ArxisStudio.Modules.Sample`. Рабочий модуль, а не
образец — `src/Modules/ArxisStudio.Modules.Terminal`.

Отличий ровно два: список модулей объявлен в самой студии
([`StudioModules.Assemblies`](src/ArxisStudio/Services/StudioModules.cs) — сюда добавляют новый
модуль), и выгрузить модуль отдельно нельзя.

Третье отличие — словари, и оно важнее, чем кажется. Своей папки у модуля нет, и текст ему дают
словари самой студии. Плагину эта дорога закрыта: ключи студии внутренние, и переименование одного
не должно менять текст в чужой панели. У переезжающего модуля строки переезжают отдельно — из
`lang/<код>.json` студии в его `lang/strings.json`.

Меню, кнопки полосы и вкладки панелей студия строит **по манифесту, не загружая сборку**: кнопка
спящего плагина стоит на месте и будит его щелчком. Поэтому `activation` (`onStartup`,
`onCommand:`, `onFileType:`, `onToolWindow:`) — не оптимизация, а часть контракта.

Общие сборки перечислены в `PluginLoadContext.IsShared`: Avalonia, `ArxisStudio.Sdk`,
`ArxisStudio.Controls`, `ArxisStudio.Icons`. Копия любой из них рядом с плагином стала бы вторым
экземпляром того же типа, и приведение упало бы. Контрактные сборки (`provides.contracts`) грузятся
в основной контекст один раз и **не выгружаются**: их обновление честно просит перезапуск, а
[`PluginContracts`](src/ArxisStudio.Extensibility/PluginContracts.cs) это говорит вместо того,
чтобы молча держать прежнюю копию.

**Разметка плагина стоит ему перезагрузки на ходу, и это измерено, а не предположено.** Плагин,
объявивший свой тип-контрола, после показа панели не выгружается — а `x:Class` это всегда свой
тип-контрола; держит его Avalonia, и студия честно жалуется «прежняя копия осталась в памяти».
Модулей это не касается: они не выгружаются и так. Замер, обходная дорога без `x:Class` и что
осталось открытым — [docs/plugin-markup.md](docs/plugin-markup.md); решение по документам ещё не
принято.

## Что нельзя двигать

`AssemblyVersion` прибит на `1.0.0.0` — **навсегда**. Плагин собирается против `ArxisStudio.Sdk` и
запоминает его имя вместе с версией; сдвиг ломает связывание у каждого уже установленного плагина.
Это проверено дорогой ценой и записано в [Directory.Build.props](Directory.Build.props). Меняются
`ArxisRelease` и `Version` — то, что версией называют люди; совместимость плагинов мерится
`sdk.min` в манифесте против `StudioSdk.Version`.

`StudioSdk.Version` (сейчас `4.0`) двигают, когда меняется контракт, и минор — когда добавляется.
`Satisfies` сравнивает мажор и минор, поэтому снятое обещание — это новый мажор, а не «оно и так
не использовалось».

## Правила, которые нарушаются молча

**Строка студии живёт в трёх файлах.** `Localization/Strings/en.json`, `ru.json` и
`templates/Arxis.Language/lang/xx.json` — в шаблоне перевода ровно те же ключи, и это закреплено
`LanguageTemplateTests`. Забыть третий значит выдать переводчику неполный шаблон.

**`%ключ%` в манифесте берётся из словаря**, и `ARX0002` говорит при сборке, если ключа нет: у
плагина смотрит `lang/strings.json`, у встроенного модуля — словарь студии. Без анализатора об
этом сказала бы студия, но в журнал и уже у пользователя.

**Интерфейс строится на `Ax*`, а не на голых виджетах Avalonia.** Панели раскладки, рамки, текст и
фигуры — можно: своего оформления они не несут. Правило проверяется `ARX0001` в коде и `ARX0006` в
разметке; оба называют замену, а где её нет — говорят и об этом. Анализатор через
`ProjectReference` не передаётся, поэтому каждый модуль и плагин подключает его строкой в своём
csproj — при заведении нового не забудьте.

**Панель прощается перед выгрузкой.** `ToolWindow.Release()` зовётся прежде, чем её сборку
выгрузят: за панелью могут стоять процессы, потоки и подписки, и отпустить их может только она.
То же у `ToolBarItem`.

**Значение цвета или размера объявляется в теме и больше нигде** — ни в шаблонах, ни в разметке,
ни в коде панелей. Это правило подмодуля `Themes.Arxis`, но нарушается оно здесь.

**Один адрес разметки на все библиотеки студии** —
`https://github.com/Arxis-Team/ArxisStudio`, объявлен `XmlnsDefinition` в каждой из них. Действует
только для сборок, на которые сослался проект, поэтому разграничение выходит само: плагину под ним
открывается ровно то, что ему разрешено. Под адрес Avalonia типы студии не объявляются намеренно —
в разметке расширений родной виджет виден по префиксу. `MarkupNamespaceTests` разбирает разметку на
ходу и проверяет по объявлениям сборок: одно имя под адресом принадлежит одной библиотеке, а
пространство с типами разметки объявлено и не забыто.

**Раскладка пишется отложенно.** [`StudioDock`](src/ArxisStudio/Services/StudioDock.cs) копит
правки и записывает через две секунды: тянут границу — десятки правок за секунду. Тест, который
ждёт файла сразу, должен звать `Flush()`.

**Вид докинга ничего не решает.** `DockView` сообщает о том, что сделал человек (`Dropped`,
`Resized`, `Hiding`, `Closing`, `Chosen`), а дерево правит владелец — `StudioDock`. Так одно и то
же дерево одинаково ведёт себя в главном окне, в оторванном и в тесте, где окна нет вовсе. Дерево
иммутабельно: `DockTree` возвращает новый узел, а не меняет старый.

**Сбой плагина не роняет студию.** Все вызовы чужого кода идут через
[`PluginGuard`](src/ArxisStudio.Extensibility/PluginGuard.cs); на третьем падении подряд плагин
перестают звать. Панель, упавшая в раскладке, заменяется заглушкой
([`PluginSurface`](src/ArxisStudio.Shell/PluginSurface.cs) ловит исключения в `Measure`/`Arrange`).
Новый вызов чужого кода добавляют через шов, а не мимо него.

## Тесты

720 тестов, headless-UI на `Avalonia.Headless.XUnit`, и пакет завязан на **xunit v3**. Тесту,
которому нужно живое дерево контролов, нужен `[AvaloniaFact]`, а не `[Fact]`: он поднимает
приложение из `TestApp` и загоняет тело в UI-поток. Рисование настоящее (`UseSkia`,
`UseHeadlessDrawing = false`) — заглушка не зовёт декодер картинок и на любой файл отвечает
болванкой нужного размера, так что «значок прочитался» проходило бы и на текстовом файле.

`TestApp` ставит **все четыре слоя стилей в том же порядке, что `App.axaml`**: Fluent, ArxisTheme,
ShellStyles, DockingStyles. Порядок решает, кто кого перекроет; без слоя оболочки проверять её
было нечем.

Тесты, трогающие общее на процесс, идут по одному —
`[Collection(StudioStateCollection.Name)]`. Общего два: `Localizer` один на процесс, и выгрузка
контекстов загрузки опирается на сборщик мусора, тоже один. Остальные классы xUnit пускает
параллельно, и это правильно — очередь заведена ровно для тех, у кого общее состояние.

Имена тестов — английская фраза с подчёркиваниями (`A_pack_made_from_the_template_works`),
сообщения в `Assert` — русские. Проверять надо наблюдаемое поведение, а не внутренние структуры.
`Thread.Sleep` вместо координации не годится: в безголовом режиме время стоит, и у пары жестов
подряд счёт щелчков сбивается — между ними ставят щелчок в стороне, а не паузу.

Внутренности студии открыты тестам через `InternalsVisibleTo` в
[ArxisStudio.csproj](src/ArxisStudio/ArxisStudio.csproj).

## Подмодули

Собираются четыре из семи: **Controls** (контролы `Ax*`, lookless), **Icons** (контуры 16×16 и
`AxIcon`), **Themes.Arxis** (палитры, шаблоны, метрики), **Fonts.Cascadia** (шрифт ресурсом).
Шрифт называет не решение, а тема.

Зарегистрированы и не собираются: **Markup** (lossless XAML DOM и round-trip), **ProjectSystem**
(модель решения, MSBuild, NuGet), **DesignEditor** (канва; ещё `net8.0` — при интеграции
поднимать). Их SHA — запись того API, против которого работал снятый код; они ждут возвращения
дизайнера. В `ArxisStudio.slnx` их нет, и работать с ними нужно их собственными решениями, они
лежат в корне каждого подмодуля.

**API подмодулей можно менять** — это не замороженные зависимости. Если интеграции нужен новый
или изменённый публичный API, правьте прямо в подмодуле и коммитьте в его репозиторий, соблюдая
его правила: у Markup, ProjectSystem и DesignEditor есть свой `CLAUDE.md`, и внутри их каталогов
он старше этого файла. Указатель подмодуля обновляется в том же коммите студии, что и правка,
которой он понадобился.

Заголовок — русская фраза о том, что стало, без префикса и без точки: «Рейки по краям окна вместо
сворачивания», «Версия сборки закреплена: плагины ссылаются на неё». Тело — проза: что было не
так, почему решено именно так, на что смотрели у Visual Studio и Rider, что уехало в подмодули.
Последняя строка — счёт: `718 тестов, 0 предупреждений. Запись 101 в плане.` Запись в
[docs/plan.md](docs/plan.md) идёт тем же коммитом, что и код.
