# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Оболочка, из которой всё остальное приходит плагинами: в самой студии нет ни одной панели и ни
одного формата документа — она умеет зоны, вкладки, меню, статус-бар и один контракт
расширяемости. Дизайнер форм, дерево решения и запуск проекта в репозитории были и сняты со
сборки в этапе 17: контракт проверялся на коде, которому он был не нужен. Дерево вернулось первым —
окном проекта, встроенным модулем на том же контракте; за ним дизайнер — пока доской форм на ядре
Surface, тоже модулем; запуск вернётся плагином.

Три документа, и они не взаимозаменяемы. [README.md](README.md) — что работает сегодня.
[docs/plan.md](docs/plan.md) — **журнал сделанного, а не опись текущего состояния**: 340 записей,
принятые решения, формат манифеста (приложение A). [docs/design-system.md](docs/design-system.md) —
дизайн-система: роли цвета и пороги контраста, сетка и плотность, типографика, иконки, поведение
контролов и цели редизайна по вехам; числа берутся оттуда, а не придумываются. Мокапа и
дизайн-проекта больше нет, и сверять с ними нечего: тесты темы проверяют правила — пороги,
кратность, наличие состояний, — а не переписанные значения.

## Команды

```bash
git submodule update --init external/ArxisStudio.Controls external/ArxisStudio.Icons external/ArxisStudio.Themes.Arxis external/ArxisStudio.Fonts.Cascadia external/ArxisStudio.Markup external/ArxisStudio.ProjectSystem external/ArxisStudio.Surface
```

```bash
dotnet build ArxisStudio.slnx
```

```bash
dotnet run --project src/ArxisStudio
```

Это для запуска руками, из своего терминала. Запуск для проверки — отдельным разделом ниже: там
студия должна пережить команду, которая её подняла, и `dotnet run` для этого не годится.

```bash
dotnet test tests/ArxisStudio.Tests
```

Один тест или один класс:

```bash
dotnet test tests/ArxisStudio.Tests --filter 'FullyQualifiedName~StudioDockTests.A_panel_comes_back_exactly_where_it_stood'
```

Плагин собирается обычным `dotnet build` — таргет упаковки приезжает вместе с SDK и раскладывает
выход в формат каталога сам, в `package/` рядом с проектом (папка в `.gitignore`). Архив и
отладочная установка — по просьбе:

```bash
dotnet build src/Plugins/Arxis.HelloPlugin -p:AxPluginPack=true
```

```bash
dotnet build src/Plugins/Arxis.HelloPlugin -p:AxPluginDeploy=true
```

Второе кладёт плагин прямо в `%AppData%/ArxisStudio/plugins/<id>`, мимо менеджера. Закрывать
студию для этого не нужно: она держит теневую копию, а не сами файлы, — выложите сборку и
нажмите «Плагины → Перезагрузить».

Плагины самого репозитория пакуют архив при каждой сборке — строкой `AxPluginPack` в своём
csproj, — и новый плагин заводят сразу с ней: без неё раскладка ложится, а поставить плагин
менеджером нечем. Забывшего называет `PluginPackagingTests`, а заодно и архив, отставший от
раскладки: он в `.gitignore`, и выключенная упаковка оставляет на диске прежний.

Отдельного линтера нет: `TreatWarningsAsErrors` включён на всё решение, и сборка идёт с нулём
предупреждений. Это не случайность и не то, что можно «пока оставить». XML-комментарии проверяет
она же: файл документации генерируется у каждого проекта под `src`, потому что без него
компилятор комментарии не разбирает вовсе, и незакрытый тег или ссылка на переименованный метод
живут незамеченными. У приложения файл остаётся в `obj` — у корня выхода лежит только студия.
Новому проекту генерацию включают сразу; забытое называет `DocumentationBuildTests`.

Данные пользователя — `%AppData%/ArxisStudio`: `settings.json`, `layout.json`,
`recent-projects.json`, `keymap.json` (его пишет только человек), `lang/`, `plugins/` (и `plugins/.disabled.json`, где помнится, кого
выключили), `restart-<номер>.json` — сессия перезапуска, живёт секунды: новая копия стирает
прочитанное, а оставшийся файл значит, что она сессию не приняла. Теневые копии — в `%TEMP%/arxis-plugin-shadow` и `arxis-contract-shadow`, чистятся
при первом обращении за сеанс. Локальная история — в машинной папке,
`%LocalAppData%/ArxisStudio/LocalHistory`: она большая и привязана к машине. Переменная
`ARXIS_LOCAL_HISTORY` переносит её, а `0` выключает — так живёт процесс тестов (`TestLocalHistory`),
и тест истории называет свою временную папку прямо. Рядом и по тому же правилу — снимки форм для плиток,
`%LocalAppData%/ArxisStudio/Previews`: кэш машины, а не файл решения. Переносит их `ARXIS_PREVIEWS`,
выключает `0` — процессу тестов (`TestPreviews`), а тест снимков называет свою папку швом дизайнера
(`UiDesignerOptions.SnapshotsFolder`).

## Проверка на живой студии

**Проверяя работу, студию запускают и управляют ею через MCP — это ожидаемый способ, а не
исключение, и спрашивать разрешения на него не нужно.** Тесты закрепляют поведение, а живая
студия отвечает на то, чего в них не видно: встала ли панель в зону, что показывает окно после
щелчка, не обрезалось ли в светлой теме. `F12` открывает те же инструменты руками —
[docs/devtools.md](docs/devtools.md).

Запускать **собранный exe**, а не `dotnet run`: порождающий процесс умирает вместе с командой и
уносит студию с собой. Перед пересборкой студию закрывают — теневая копия есть у плагинов, а не
у неё самой, и запущенная студия держит свои сборки: пересборка падает с `MSB3027`/`MSB3021`,
называя процесс и его pid. Предупреждения, которыми такой прогон обрастает, к коду отношения не
имеют и уходят вместе с блокировкой.

```bash
dotnet build ArxisStudio.slnx && powershell -c "Start-Process 'src\ArxisStudio\bin\Debug\net10.0\ArxisStudio.exe'"
```

Историю студии, поднятой для проверки, уводят во временную папку — `$env:ARXIS_LOCAL_HISTORY` в
той же команде PowerShell перед `Start-Process`: служба проектов открывает историю при подъёме
модуля, ещё на Welcome, и без переменной живая проверка писала бы в историю человека. Снимки форм
уводят так же — `$env:ARXIS_PREVIEWS`: форма, открытая на проверке, иначе легла бы снимком в папку
человека.

Конечная точка поднимается сразу при старте, ждать открытия окна инструментов не надо. Порты
заняты так: **5171** — студия, **5172** — витрина контролов, **5173** — витрина иконок. Обе
витрины живут в подмодулях, в `ArxisStudio.slnx` их нет и запускаются они своими решениями
(`dotnet run --project external/ArxisStudio.Controls/samples/Controls.Gallery`). Вторая студия
рядом с первой — `ARXIS_SINGLE_INSTANCE=0` и `ARXIS_DEVTOOLS_MCP_PORT=5199`; остальные переменные в
[docs/devtools.md](docs/devtools.md).

**Студия одна на папку данных.** Вторая, запущенная над той же `%AppData%/ArxisStudio`, не
поднимается, а отдаёт первой свои аргументы и уходит: двойной щелчок по решению при открытой
студии открывает его в ней, щелчок по значку выводит её вперёд. Поэтому проверка, которой нужна
вторая студия рядом с первой, снимает это правило переменной `ARXIS_SINGLE_INSTANCE=0` — иначе
вторая молча отдаст управление первой, и `list_windows` на новом порту не ответит ничем. Две
студии над одной папкой спорят за её файлы: раскладку запишет та, что закроется последней.

Клиент MCP сессии подключается один раз, на старте. Если студия поднялась позже, инструменты в
этой сессии останутся недоступными до переподключения — но с конечной точкой можно говорить и
напрямую, обычным JSON-RPC по HTTP. Клиента хватает вот такого:

```python
import json, urllib.request
def call(name, args=None, port=5171):
    body = json.dumps({"jsonrpc":"2.0","id":9,"method":"tools/call",
                       "params":{"name":name,"arguments":args or {}}}, ensure_ascii=True).encode("ascii")
    req = urllib.request.Request(f"http://127.0.0.1:{port}/", data=body,
        headers={"Content-Type":"application/json","Accept":"application/json, text/event-stream"})
    return json.loads(urllib.request.urlopen(req, timeout=40).read().decode("utf-8"))
```

`ensure_ascii=True` здесь обязателен: русский запрос, посланный через `curl` из шелла, доезжает
до студии искажённым, и `find_elements` отвечает «ничего не найдено» на текст, который в окне
есть. Экранирование в `\uXXXX` снимает вопрос целиком.

Порядок работы задают сами инструменты: `list_windows` первым — всё остальное берёт `elementId`,
и живут эти номера, пока жив элемент. Дальше `find_elements` превращает видимый текст в номер,
`click` его нажимает, `screenshot` показывает, что вышло, `get_problems` со `scan: true`
подметает дерево на сломанные привязки, `run_variants` перечитывает студию в светлой теме, при
двойном тексте и в узком окне.

Шесть мест, где легко обмануться:

- **Неизвестный параметр не отвергается, а подменяется умолчанием.** Поле называется
  `elementId`; передав `id`, вы получите не ошибку, а дерево или снимок «главного окна» — то есть
  `desktop.MainWindow`, которым после перехода в студию остаётся уже скрытое окно Welcome.
- **«Nothing in the application handled it» — про флаг `e.Handled`, а не про то, что обработчик
  не вызвался.** Обработчики студии его чаще всего не ставят, так что судить надо по
  последствию: позвать `list_windows` или `screenshot` и посмотреть, что стало.
- **Точка отвечает раньше, чем появляется окно.** Инструменты подключаются в `App.Initialize`, а
  под заставкой ещё поднимаются модули и плагины, поэтому первый `list_windows` вполне может
  ответить `SplashWindow` — и поиск по видимому тексту тогда не найдёт ничего. Дождитесь
  `WelcomeWindow`, а не просто открытого порта.
- **Студия открывается на Welcome.** До главного окна её доводят две двери: кнопка «Каркас
  студии» — в пустой каркас — и строка недавнего проекта, открывающая его. Панелей, полосы и
  раскладки до этого нет вовсе. Названный в командной строке проект Welcome пропускает вовсе.
- **`run_variants` оставляет активным главное окно.** Открытый модальный диалог после него уже
  не в фокусе, и `press_key` без `elementId` уходит в главное окно — в ту строку, где стоял
  человек. Кнопку диалога после вариантов жмут `click` по её номеру.
- **Модальность инструменты не держат.** `click` доставляет нажатие и в окно, которое система
  выключила под модальным: щелчок по двери Welcome при открытых настройках откроет второе окно
  настроек. Человеку так не попасть — жмут в том окне, что в `list_windows` отмечено `[active]`.
  А `run_variants` читает главное окно, а не модальное поверх него: варианты окна настроек
  держат тесты кегля, а тему смотрят снимком после переключения.

Запущенное за собой закрывают по номеру процесса: `Start-Process -PassThru` его отдаёт, а
`Stop-Process -Id <номер> -Force` закрывает. По имени закрывать нельзя — рядом может работать
студия человека, со своей историей в `%LocalAppData%`, и её эта папка: проверка её не чистит.
Следов в репозитории проверка не оставляет — трогается только `%AppData%/ArxisStudio`, и то
обычной работой студии: раскладка пишется по таймеру во время сеанса, а `Farewell` дописывает
остаток при штатном закрытии, которое `-Force` как раз пропускает.

**Перезапуск меняет номер процесса.** Студия, перезапустившаяся на проверке, — уже другой процесс, и
номер от `Start-Process -PassThru` принадлежит умершему. Закрывают новую: её номер пишет в журнал
прежняя («Новая копия (процесс …) приняла сессию»), а родитель у неё — прежний номер. Клиент MCP
сессии остался у прежней, с новой говорят напрямую по тому же порту. Файлов `restart-*.json` после
удачного перезапуска в папке данных нет — оставшийся значит, что новая копия сессию не приняла.

| [ArxisStudio.Projects.Contracts](src/Modules/ArxisStudio.Projects.Contracts) | контракт службы проектов: состояние, перемены, дорога из контекста | Sdk, ядро ProjectSystem — и ни одного движка |

| [ArxisStudio](src/ArxisStudio) | приложение и вся склейка | всё |

Направление держит сборка, а не уговор. Таргет `AxDockingBoundary` в
[ArxisStudio.Docking.csproj](src/ArxisStudio.Docking/ArxisStudio.Docking.csproj) валит сборку с
`AXD1001`, если у движка объявлена ссылка на Sdk, Shell или Extensibility, а `DockingBoundaryTests`
смотрит на готовую сборку. Причина в самом сообщении: раскладка переживает выключение плагина и
уезжает в файл, поэтому узел дерева, удержавший объект плагина, навсегда оставит в памяти его
контекст загрузки. Движку нужны идентификаторы, живые контролы держит студия.

У локальной истории граница строже: ссылок нет никаких, и `AXH1001` валит сборку на первой же,
а `LocalHistoryBoundaryTests` смотрит на готовую. Журнал и хранилище переживают студию и читаются
её следующей версией — их формат не должен зависеть ни от интерфейса, ни от движка, ни от модели
проектов. Что считать файлом проекта и когда снимать, решает служба проектов: библиотека хранит
то, что ей дали. Библиотеку везёт модуль «Проекты» в своём `bin`, тесты называют её так же, как
движки, — только для компиляции.

У SDK то же правило словами: реализации студии в нём быть не должно. Исключение одно и осознанное —
библиотека контролов: интерфейс плагина строится только на `Ax*`, и ссылаться на неё плагин обязан
в любом случае.

## Две доставки, один контракт

Внешний плагин — папка с `plugin.json` и сборкой; та же папка в zip — это `.axplugin`. Живёт в
своём выгружаемом `AssemblyLoadContext`, грузится из теневой копии, перезагружается на ходу.
Встроенный модуль — такая же папка с `module.json` и `bin/`, только приезжает она со студией,
живёт в основном контексте и отдельно не выгружается. **Код между режимами переносится без правок**, и в репозитории есть образец каждого:
`src/Plugins/Arxis.HelloPlugin` и `src/Modules/ArxisStudio.Modules.Sample`. Единственный
редактор документов — пробный `src/Plugins/Arxis.CodeViewer` на AvaloniaEdit: он показывает
текстовый файл на просмотр и уйдёт, когда появится настоящий; чем платит плагин за чужую
библиотеку контролов, сказано в [docs/plugin-markup.md](docs/plugin-markup.md).
Рабочих модулей шесть, а не образцов — `src/Modules/ArxisStudio.Modules.Terminal`,
`src/Modules/ArxisStudio.Modules.Console`,
`src/Modules/ArxisStudio.Modules.Projects` — служба без единой панели, отдающая соседям контракт
`ArxisStudio.Projects.Contracts` (объявлен в `provides.contracts`), — и
`src/Modules/ArxisStudio.Modules.Project`, окно проекта: первый потребитель этого контракта, и берёт
он его так же, как взял бы плагин; второй потребитель — `src/Modules/ArxisStudio.Modules.UiDesigner`,
доска форм решения на ядре Surface (о ней ниже). Служб в контракте пять, и разведены они
по тому, чем занят берущий: модель — `context.Projects()`, сборка — `context.Build()`, пакеты —
`context.Packages()`, файлы — `context.Files()`, история — `context.History()`. Файлы решения правят
только через службу файлов: она переписывает ссылки файла проекта, перечитывает модель и пишет
действие в локальную историю, а правка мимо неё расходится со снимком. Перечитывает она один раз: на
время правки и перечитывания слежение придерживает свои приговоры и сверяет их потом со свежим
снимком, а переписанные входы оценки узнаёт по отпечатку (`IWatchHold`). Отмена и возврат из истории
ходят той же дорогой (`FilesService.EditAsync`) — иначе разошлись бы со снимком так же. Ею же идёт и
запись (`WriteAsync`) — так сохраняет документ редактор: сверка с тем, что он видел на диске, история
действием-сохранением, мимо которого проходит Ctrl+Z окна проекта, и отпечаток, по которому слежение
за содержимым (`ContentChanged`, живёт, пока его слушают) узнаёт своё сохранение. Сборки дизайнера
идут профилем (`OpenProfile`): своя оценка того же решения с выходом в `bin/ArxisStudio/`, на той же
полосе и следом за каждой загрузкой службы. Автору плагина об этом написано в [docs/projects.md](docs/projects.md), и
примеры оттуда компилируются тестом: правка контракта, их сломавшая, падает там. Имена близки, и
путать их нельзя: `arxis.projects` — служба, `arxis.project` — окно; сравнения в коде точные.
Превью картинок на плитках окна проекта просит колонка и только для видимых плиток: `WrapPanel`
не виртуализирован, и жадный декод прочёл бы папку целиком. Растр держит служба превью и
освобождает его в потоке интерфейса — вне его освобождение ждёт диспетчера. Размер картинки до
декода спрашивает `SKCodec`: `Bitmap.DecodeToWidth` растягивает мелкое. Модуль ссылается на
SkiaSharp только для компиляции, и версия в `Directory.Packages.props` двигается вместе с
Avalonia.Skia. Файл, который рисует поставщик превью студии (`IStudioFilePreviews`), — форма со снимком, —
идёт той же дорогой: картинку отдаёт поставщик, а уменьшает, держит и освобождает её служба. Его превью
меняется и без перемены файла — снят первый снимок, — поэтому в ключе кэша есть номер перемены
(`Changed` поставщика), а «старше файла» едет с растром отметкой в углу плитки.

Шестой — `src/Modules/ArxisStudio.Modules.Xaml`, служба XAML (`arxis.xaml`): тоже без единой панели и
тоже отдаёт соседям контракт — `ArxisStudio.Xaml.Contracts`. Документы разметки решения у неё живые:
своя история правок у каждого и объекты, построенные из текста в **поколении** — типах проекта,
загруженных в выгружаемый контекст адаптером ProjectSystem (`ProjectDesignHost`). Своего MSBuild у неё
нет: снимки и сборки даёт профиль дизайна (`StudioDesignSource`), пишет она `IStudioFiles.WriteAsync` со
сверкой ожидаемого (`StudioDesignWriter`), а перемены на диске слышит через `ContentChanged`. Служб две —
документы (`context.XamlDocuments()`) и поколение (`context.XamlDesign()`). Документ один на файл и живёт,
пока не отпущена последняя аренда; показ (`ShowAsync`) один на документ. Сессия одна на решение:
поднимается первым открытым документом, кончается с решением, со службой или через простой после
последнего отпущенного документа. На замену поколения участники (`Register`) отпускают своё раньше
показов — холст успевает заморозить кадр с корнем, — а берут новое после них, когда новый корень уже
стоит. Участников хост зовёт, держа свою очередь, поэтому ни показ, ни
участник не ждут там службу: приложение формы показ берёт уже после замены. Не ушло поколение —
служба просит перезапуск (`IStudioRestart`). Автору плагина написано [docs/xaml.md](docs/xaml.md), и
примеры оттуда компилируются.

Отличий ровно два: список модулей объявлен в самой студии
([`StudioModules.Assemblies`](src/ArxisStudio/Services/StudioModules.cs) — сюда добавляют новый
модуль, а в [ArxisStudio.csproj](src/ArxisStudio/ArxisStudio.csproj) — ссылку на него с пометками
`StudioModule="true" Private="false" ExcludeAssets="runtime"`), и выгрузить модуль отдельно нельзя.

**У корня выхода — только сама студия.** Платформа лежит в `lib/`, у корня остаются exe, сборка
студии и два файла среды, а у каждого модуля **своя папка в `modules/`, формой как у установленного
плагина**: манифест в корне, сборки в `bin/`.

```
modules/arxis.terminal/module.json
modules/arxis.terminal/bin/{ArxisStudio.Modules.Terminal,Porta.Pty,XTerm.NET}.dll
```

Имя папки — идентификатор из манифеста; читает его сам модуль, а не студия. Правила раскладки —
[build/ArxisStudio.Library.targets](src/ArxisStudio/build/ArxisStudio.Library.targets) и
[build/ArxisStudio.Modules.targets](src/ArxisStudio/build/ArxisStudio.Modules.targets); состав модуль
отдаёт сам (цель `StudioModuleFiles` в
[src/Modules/Directory.Build.targets](src/Modules/Directory.Build.targets)), а дорогу к обеим папкам
основной контекст загрузки получает от
[`StudioAssemblyFolder`](src/ArxisStudio/Services/StudioAssemblyFolder.cs): платформу он ищет в самой
папке, модули — в `bin` каждого.

**Один файл — один модуль.** Модули живут в одном основном контексте загрузки, где имя грузится
ровно один раз, и две папки с одноимённой сборкой дали бы две копии на диске и одну работающую.
`AXL1002` валит сборку, называя файл и всех его владельцев; общей сборке место в `lib/` — её проект
называют прямо в `ArxisStudio.csproj`, — а чужой контракт подключают `Private="false"
ExcludeAssets="runtime"`: возит его владелец. Идентификатор, который не прочитался из манифеста,
называет `AXL1003`.

**В `Main` нет ничего, кроме двух строк дороги и вызова `Start`**, и это условие запуска, а не стиль:
JIT компилирует метод целиком до первой его строки, и тип из `lib`, названный в точке входа, роняет
студию раньше, чем встанут резолверы. Правило закреплено тестом. Нативные библиотеки пакетов
остаются в `runtimes/` у корня. Транзитивные ссылки на проекты у приложения выключены, поэтому
проект, нужный самой студии, в её csproj называют прямо — иначе он окажется только в `modules/`. За
раскладкой смотрит `StudioLayoutTests` на собранном выходе. Папка встроенного модуля — та, что над
его `bin/`, и контракт он объявляет от неё же (`bin/…`), слово в слово как плагин.

Словари у модуля свои, в его `lang/`, и дорога к ним та же, что у плагина: чужих ключей — ни
студии, ни соседа — в словаре расширения не видно. Ключи студии внутренние, и переименование одного
не должно менять текст в чужой панели; модуль от этого правила не освобождён, и тем он и
переносится во внешний плагин перекладыванием папки — вместе со строками, а не отдельно от них.
Прежде словарём модулю служили словари студии, и переезд был неполным (записи 231–233).

Меню, кнопки полосы и вкладки панелей студия строит **по манифесту, не загружая сборку**: кнопка
спящего плагина стоит на месте и будит его щелчком. Поэтому `activation` (`onStartup`,
`onCommand:`, `onFileType:`, `onToolWindow:`, `onNewItem:`) — не оптимизация, а часть контракта. Спящий — такой
же житель студии, как поднятый: выключая его, снимают кнопки, сочетания и запись среди ждущих
(`PluginHost.Withdraw`), иначе первое его событие поднимет выключенного. Сочетания манифеста
заявляются один раз на жизнь хозяина — на старте и после каскада, а не до него: уход прежней копии
стирает всё, что на неё записано.

Пункты «Добавить ▸» (`newItems`) тоже живут по манифесту: каталог и файлы по шаблонам собирает
служба студии [`StudioNewItems`](src/ArxisStudio/Services/StudioNewItems.cs) (`IStudioNewItems`),
не поднимая расширение, а пункт вида `code` будит хозяина событием `onNewItem:` и зовёт его класс
`[NewItem]` через шов. На диск служба не пишет — кладёт тот, кто показал меню, через
`IStudioFiles.CreateAsync`. Шаблоны — данные: `templates/**` стоит в `DefaultItemExcludes` у плагина
и у модуля и едет в пакет и в `modules/<id>/templates`; пропажу называют `AXP1007` и `AXL1004`. У
плагина в тот же список исключён и `package/`: раскладка лежит в каталоге проекта, и копия шаблона
`.cs` из прошлой сборки иначе компилировалась бы следующей.

**Тяга между панелями — служба студии, а не платформы.** `IStudioDragDrop`
([`StudioDrags`](src/ArxisStudio/Dragging/StudioDrags.cs)) несёт данные между окнами студии захватом
указателя, как вкладки докинга, а не системной тягой: мышь инструментов студии и тестов ведёт её так
же, как настоящая. Окна спрашиваются по точке экрана — оторванные раньше главного, — цель — ближайший
к курсору элемент с `StudioDragDrop.AllowDrop`, а подсказку у курсора и курсор ведёт студия над любым
своим окном. Цели служба не помнит дольше тяги — выгруженный плагин ею не задержится, — а упавший
обработчик цели выпадает из тяги и приписывается по стеку, как всякое исключение из обработчика
плагина. Договор цели — ответ в `DragOver` каждый раз с отказа, один разрешённый эффект, `DragLeave` и
после `Drop` — и обе дороги источника — `DragAsync` и сеанс `Begin` для источника со своими целями —
описаны для автора в [docs/drag-drop.md](docs/drag-drop.md), и примеры оттуда компилируются тестом.
Источник со своими целями решает «своё или чужое» попаданием сеанса (`ElementAt`), а не своего окна:
то не видит оторванного окна поверх и нашло бы свою цель под чужой панелью. Окно проекта так и
носит: свои каталоги отвечает само, за край — сеансом, и чужим разрешает копию и ссылку, но не
перенос. В безголовом тесте попадание идёт по сцене отрисовки, а новому окну её кладёт только такт:
`ForceRenderTimerTick` перед первым `Over`, иначе курсор над целью придётся на пустое место.

**Превью файлов — служба студии, и рисует их тот, кто понимает файл.** `IStudioFilePreviews`
([`StudioFilePreviews`](src/ArxisStudio/Services/StudioFilePreviews.cs)) — поставщики по расширению, один
на расширение, и перемены их картинок. Плагину служба выдаётся обёрткой с его идентификатором, и
выгрузка снимает его поставщиков и подписки (`RemoveOwnedBy`): оставшись в реестре, они держали бы
контекст выгруженного. Картинка ходит закодированной — растр уменьшает, держит и освобождает
показывающий, — поставщика студия зовёт в потоке интерфейса через шов, и отмена ему не засчитывается.
Поставщик `.axaml` — дизайнер со снимками форм, показывающий — окно проекта. Договор для автора —
[docs/file-previews.md](docs/file-previews.md), примеры оттуда компилируются тестом.

Общие сборки перечислены в `PluginLoadContext.IsShared`: Avalonia, `ArxisStudio.Sdk`,
`ArxisStudio.Controls`, `ArxisStudio.Icons` — семейством, то есть именем целиком или с точкой за
ним, а не по первым буквам: чужая `AvaloniaEdit` остаётся своей у плагина, — и точным именем
`ArxisStudio.ProjectSystem`, ядро модели проектов: снимки решения видят все плагины, а его движки (`.MSBuild`, `.NuGet`) общими не
становятся — их держит служба проектов. Точными же именами общие `ArxisStudio.Markup` и
`ArxisStudio.Markup.Xaml`, синтаксис разметки: документ, его редактор и путь элемента ходят через
контракт службы XAML, а загрузчик (`.Markup.Xaml.Loader`) и адаптер ProjectSystem держит служба XAML.
Рантайм-загрузчик Avalonia, на котором стоит загрузчик Markup, — из семейства Avalonia и лежит в `lib/`.
Копия любой общей сборки рядом с плагином стала бы вторым
экземпляром того же типа, и приведение упало бы. Поверхности ядра, синтаксиса Markup и контрактов служб проектов и XAML закреплены в
`tests/ArxisStudio.Tests/Surfaces`: сдвиг указателя или правка контракта, их поменявшие, падают там, а не у автора плагина. Контрактные сборки (`provides.contracts`) грузятся
в основной контекст один раз и **не выгружаются**: их обновление честно просит перезапуск, а
[`PluginContracts`](src/ArxisStudio.Extensibility/PluginContracts.cs) это говорит вместо того,
чтобы молча держать прежнюю копию.

**Своя зависимость едет с плагином, а платформа — нет.** Таргет упаковки включает
`CopyLocalLockFileAssemblies` сам: библиотеке сборки пакетов в выход не копируют, и пакетная
ссылка плагина осталась бы одной строкой в его `deps.json` — на машине автора её находит кэш
NuGet, а у человека плагин падает на первом же типе из неё. Перевод пакета едет в папке своего
языка: сложенный в корень `bin/`, он не находится ничем. Не едут, кроме общих контрактов,
спутники Avalonia, которые студия везёт в `lib/` — `SkiaSharp`, `HarfBuzzSharp`,
`MicroCom.Runtime`, `Tmds.DBus.Protocol`: сборку, которой у плагина нет, его контекст спрашивает
у основного, а копия SkiaSharp приехала бы без нативной библиотеки. Раскладку пакета сторожит
`PluginPackagingTests`, и набор «что везёт студия» он берёт у собранной студии, а не списком.

**Разметка плагина перезагружается на ходу — с `x:Class` и без, и держит это выгрузка, а не удача.**
Свойство Avalonia кэширует метаданные для каждого типа, у которого их спросило оформление, словарём
с сильным ключом, и тип-контрол плагина, побывавший на экране, не давал контексту выгрузиться.
[`PluginLoadContext.Release`](src/ArxisStudio.Extensibility/PluginLoadContext.cs) снимает эти типы открытым
`AvaloniaPropertyRegistry.UnregisterByModule` — рядом со сбросом кэша загрузчика ресурсов, и новую
уборку перед выгрузкой ставят туда же. Замер, дорога без `x:Class` и чем она платит —
[docs/plugin-markup.md](docs/plugin-markup.md).

**Кроме плагина со своими свойствами, событиями или классовыми обработчиками Avalonia** — своими или
его библиотеки, как AvaloniaEdit у просмотрщика. Записи самого типа `UnregisterByModule` не снимает, у
реестра событий снятия нет, и такой плагин держится в памяти до перезапуска. Дочищать это рефлексией
на запись студия не берётся — по решению владельца, — а перезапускается. Спущенный такой плагин
встаёт в `StudioPlugins.AwaitingRestart` — туда же идёт пересобранный контракт и застрявший без
видимой причины после передышки, — и человеку говорится только «Требуется перезапуск ArxisStudio»:
владельцы свойств (`PluginHost.Pinned`) — разговор для автора, и ведётся он в журнале. Свойства
спрашиваются закрытым словарём реестра `_registered` только на чтение: открытый `GetRegistered`
прогоняет статические конструкторы и сам завёл бы свойства, приковав к памяти того, о ком спрашивают.

**Перезапуск возвращает открытое.** Вопрос задаёт [`StudioRestart`](src/ArxisStudio/Services/StudioRestart.cs)
— только о новом поводе и только от открытого окна: закрытое обнуляет `Owner`, а модальный диалог
без хозяина роняет студию из `async void`, поэтому о «Сохранить» спрашивает тот, кто открывал
настройки, после их закрытия. Процесс и окна — у
[`StudioRestarter`](src/ArxisStudio/Services/StudioRestarter.cs), которого приложение ставит студии
исполнителем: сессия ([`StudioSession`](src/ArxisStudio/Services/StudioSession.cs)) снимается до
первого закрытия, новая копия поднимается раньше, чем закроется прежняя, и ответ её — стёртый файл
сессии; до ответа прежняя не трогает ничего. Порядок возврата — в [`StudioResume`](src/ArxisStudio/Services/StudioResume.cs):
проект, документы, выборы групп, показанный документ, каретка, окно настроек. Окно настроек
закрывают для перезапуска `CloseForRestart`: его крестик отменяет первое закрытие всегда, и закрытие
студии отменилось бы вместе с ним. Перезапуск из окна сперва дописывает несохранённое
(`SaveAsync(live: false)` — плагины не опускаются), а не записалось — не перезапускается. Место
окна снимается обычными границами: развёрнутое отвечает размером экрана, и помнит их
[`NormalBounds`](src/ArxisStudio/Services/NormalBounds.cs), один на главное окно и окно настроек.
Дорога процессов и что не возвращается — [docs/devtools.md](docs/devtools.md#перезапуск).

## Что нельзя двигать

`AssemblyVersion` прибит на `1.0.0.0` — **навсегда**. Плагин собирается против `ArxisStudio.Sdk` и
запоминает его имя вместе с версией; сдвиг ломает связывание у каждого уже установленного плагина.
Это проверено дорогой ценой и записано в [Directory.Build.props](Directory.Build.props). Меняются
`ArxisRelease` и `Version` — то, что версией называют люди; совместимость плагинов мерится
`sdk.min` в манифесте против `StudioSdk.Version`.

`StudioSdk.Version` (сейчас `7.17`) двигают, когда меняется контракт, и минор — когда добавляется.
`Satisfies` сравнивает мажор и минор, поэтому снятое обещание — это новый мажор, а не «оно и так
не использовалось».

Обещание — не только SDK. Набор контролов, иконки и ядро модели проектов плагин видит общими, и их
поверхность записана в `tests/ArxisStudio.Tests/Surfaces` вместе с номером, при котором её
записали. Разошлась — тест требует сдвига номера (добавленное — минор, снятое — мажор) и только
после сдвига отдаёт новую запись: перенести поверхность мимо номера нечем.

## Правила, которые нарушаются молча

**Строка студии живёт в трёх файлах.** `Localization/Strings/en.json`, `ru.json` и
`templates/Arxis.Language/lang/xx.json` — в шаблоне перевода ровно те же ключи, и это закреплено
`LanguageTemplateTests`. Забыть третий значит выдать переводчику неполный шаблон.

**Словарь расширения называется кодом языка** — `lang/en.json`, `lang/ru.json`, `lang/de.json`,
той же формой, что у самой студии. Английский особый: его читают, когда файла текущего языка нет,
и потому он есть у каждого расширения. Языки одного расширения описывают одни ключи, а общую ветку
меню (`%menu.tools%`) все называют одним словом в каждом языке: ветки сходятся по переведённому
тексту, и расхождение дало бы два раздела, одинаковых с виду. Оба правила держит
`ExtensionStringKeysTests`. Расширение, собранное до SDK 7.0, студия поднимает — прежний старший
номер `Satisfies` пропускает, — но его `lang/strings.json` не читает, и подписи становятся
`!ключами!`; причину называет журнал. Увидев ключи, смотрят туда, а свой пример переустанавливают
`-p:AxPluginDeploy=true`.

**`%ключ%` в манифесте берётся из словаря**, и `ARX0002` говорит при сборке, если ключа нет: у
плагина и у модуля смотрит `lang/en.json` в его папке. Без анализатора об
этом сказала бы студия, но в журнал и уже у пользователя. Словарь, который студия не прочтёт,
называет `ARX0012` — только помеченный сборкой ролью `AxStrings` (`default` или `translation`).
Метит их сборка сама и одинаково: плагину — таргет SDK, модулю — общий
[src/Modules/Directory.Build.targets](src/Modules/Directory.Build.targets), — так что новый модуль
приходит с проверкой, а не забывает её подключить.

**Путь из манифеста остаётся в папке плагина.** Всё, что манифест называет путём, — `entry`,
`icon`, контракт, словарь пакета — и идентификатор, который становится именем папки, проходит через
[`PluginPaths`](src/ArxisStudio.Extensibility/PluginPaths.cs). `Path.Combine` здесь не защита:
корневой второй аргумент он возвращает как есть, и `"id": ".."` при установке с заменой стирал папку
данных студии. Новое поле манифеста с путём читают через `Inside`, а не мимо него.

**Интерфейс строится на `Ax*`, а не на голых виджетах Avalonia.** Панели раскладки, рамки, текст и
фигуры — можно: своего оформления они не несут. Правило проверяется `ARX0001` в коде — созданием и
наследованием: пустой наследник виджета обходил запрет, — и `ARX0006` в разметке; оба называют
замену, а где её нет — говорят и об этом. Анализатор через
`ProjectReference` не передаётся, поэтому каждый модуль и плагин подключает его строкой в своём
csproj — при заведении нового не забудьте.

**Панель прощается перед выгрузкой.** `ToolWindow.Release()` зовётся прежде, чем её сборку
выгрузят: за панелью могут стоять процессы, потоки и подписки, и отпустить их может только она.
То же у `ToolBarItem`. Идёт прощание своей дорогой шва — `PluginGuard.Farewell`, а не рабочей:
рабочая отказывает отключённому за сбои, а прощаться надо как раз с ним. Перезапуск упавшей панели
из заглушки прощается с прежним экземпляром раньше, чем строит новый.

**Значение цвета или размера объявляется в теме и больше нигде** — ни в шаблонах, ни в разметке,
ни в коде панелей. Это правило подмодуля `Themes.Arxis`, но нарушается оно здесь. У расширений его
держит сборка — `ARX0008`–`ARX0010` называют ключ вместо числа, договор описан в
[docs/plugin-markup.md](docs/plugin-markup.md), — а у самой студии храповики в обоих репозиториях:
`LiteralSpacingTests` считает отступы, `LiteralSizeTests` — длины, толщины и разрядку, оба в разметке
и в коде, а `LiteralRadiusTests` — скругления. Все они дошли до нуля в вехе метрик и работают
теперь запретом, а исключения названы правилом, а не списком: поправка меньше двух пикселей — не
зазор, размер окна в его открывающем теге — не вёрстка, картинка релиза заставки — рисунок, ширина
канвы плагина — дело плагина, константа в коде называет число, а не ставит длину контролу. Ключ темы, названный строкой в коде студии, модулей, плагинов,
шаблона, контролов и значков, сверяет с темой `CodeResourceKeysTests`, а в разметке —
`MarkupResourceKeysTests`: опечатка в ключе не валит ни сборку, ни показ. У расширений ту же
опечатку при сборке называет `ARX0009` вместе с похожим ключом; словари темы вшиты в анализатор все,
звёздочкой, и что он знает каждый ключ, названный студией, держит `ThemeValueAnalyzerTests`. Размер значка — `IconPixelTests`, тоже запретом, и не ради порядка: набор нарисован в
клетке 16, и `AxIcon` сводит обводку к целым пикселям только там, где клетка в них ложится, а 18 или
20 точек не ложатся ни при каком обычном масштабе. Растянуть значок можно одним способом —
лестницей плитки окна проекта, 32…128 шагом 16: ключом её ступени у темы или ступенью, которую
колонка поставила списку (`TileMetrics.Glyph`). На плитке стоит только силуэт набора из прямых, и
где единица сетки не целая, `AxIcon` сажает его вершины на пиксели сам; тест мерит кадром каждую
ступень на каждом масштабе. Другой ключ на размере значка тест называет так же, как число.

**Один адрес разметки на все библиотеки студии** —
`https://github.com/Arxis-Team/ArxisStudio`, объявлен `XmlnsDefinition` в каждой из них. Действует
только для сборок, на которые сослался проект, поэтому разграничение выходит само: плагину под ним
открывается ровно то, что ему разрешено. Под адрес Avalonia типы студии не объявляются намеренно —
в разметке расширений родной виджет виден по префиксу. `MarkupNamespaceTests` разбирает разметку на
ходу и проверяет по объявлениям сборок: одно имя под адресом принадлежит одной библиотеке, а
пространство с типами разметки объявлено и не забыто.

**Раскладка пишется отложенно.** [`StudioDock`](src/ArxisStudio/Services/StudioDock.cs) копит
правки и записывает через две секунды: тянут границу — десятки правок за секунду. Тест, который
ждёт файла сразу, должен звать `Flush()`.

**Вид докинга ничего не решает.** `DockView` сообщает о том, что сделал человек (`Dropped`,
`Resized`, `Hiding`, `Closing`, `Chosen`), а дерево правит владелец — `StudioDock`. Так одно и то
же дерево одинаково ведёт себя в главном окне, в оторванном и в тесте, где окна нет вовсе. Дерево
иммутабельно: `DockTree` возвращает новый узел, а не меняет старый. Новое дерево, разошедшееся с
прежним одними долями (`DockTree.Alike`), вид ставит в те же сетки, а не перестраивает окно: на
границе стоит каретка, и перестройка уносила её вместе с разделителем. Границу вид слушает ходом
(`AxSplitter.Moved`), а не концом тяги — стрелками её тоже двигают.

**Сбой плагина не роняет студию.** Вызовы кода уже поднятого плагина идут через
[`PluginGuard`](src/ArxisStudio.Extensibility/PluginGuard.cs); на третьем падении подряд плагин
перестают звать — подряд буквально: прошедший вызов счёт обнуляет, — и отключают один раз, сколько
бы докладов ни пришло следом. Счёт закрыт замком: доклады приходят и из потока финализатора. Панель, упавшая в раскладке, заменяется заглушкой
([`PluginSurface`](src/ArxisStudio.Shell/PluginSurface.cs) ловит исключения в `Measure`/`Arrange`).
Новый вызов чужого кода добавляют через шов, а не мимо него: редакторы документов идут через него
на каждой дороге — постройка, вопрос, открытие, показ, сохранение, вопрос о закрытии, — а закрытие,
как всякое прощание, прощальной дорогой (`FarewellAsync`). Упавший вопрос о закрытии — не отказ:
сломанный документ не держит окно, — а упавшее сохранение — отказ: закрыть, не сохранив, значит
потерять правку. Окно закрывается синхронно, а документы решают асинхронно, поэтому при нужде первое
закрытие отменяется и повторяется после ответа (`StudioClosing`); без несохранённого и без документа,
решающего о себе, окно закрывается сразу, как прежде.

**У команды один хозяин.** Занятую команду реестр другому не отдаёт и говорит об этом в журнал;
своё перезаявить можно, а заявка студии вытесняет чужую. Идентификатору команды плагина нужна его
приставка.

У подъёма шов **свой**, и это не упущение: `Activate` и `Start` зовутся из
[`PluginHost`](src/ArxisStudio.Extensibility/PluginHost.cs) напрямую, потому что считать падения
ещё не поднятого плагина некому и незачем — он просто не поднимется. Роль шва там играет фильтр
`catch`, и поэтому он широкий: ловится всё, кроме нехватки памяти и переполнения стека. Пока он
перечислял беды по именам, неназванная уносила студию целиком — `NullReferenceException` из чужого
`Activate` не был назван. Сужать его обратно нельзя. Внутри шва стоит и конструктор контекста
загрузки — он читает `.deps.json` плагина и бросает на обрезанном, — а сбой на середине подъёма
останавливает тех, кого успел позвать: службы, потом точки входа, включая упавшего.

Запись у плагина в хосте одна — поднятая или с ошибкой: новая попытка прежнюю ошибку вытесняет, а
встроенность спрашивают признаком `IsBuiltIn`, не отсутствием контекста. `PluginHost.Loaded` —
снимок: его читают и не из потока интерфейса.

## Тесты

2154 теста, headless-UI на `Avalonia.Headless.XUnit`, и пакет завязан на **xunit v3**. Тесту,
которому нужно живое дерево контролов, нужен `[AvaloniaFact]`, а не `[Fact]`: он поднимает
приложение из `TestApp` и загоняет тело в UI-поток. Рисование настоящее (`UseSkia`,
`UseHeadlessDrawing = false`) — заглушка не зовёт декодер картинок и на любой файл отвечает
болванкой нужного размера, так что «значок прочитался» проходило бы и на текстовом файле.

`TestApp` ставит **все три слоя стилей в том же порядке, что `App.axaml`**: ArxisTheme,
ShellStyles, DockingStyles. Порядок решает, кто кого перекроет; без слоя оболочки проверять её
было нечем. Чужой базовой темы под ними нет ни здесь, ни в студии: окно, окно попапа и простые
контейнеры одевает сама тема, и дыра в её покрытии видна сразу — подменить её собой некому.

Тесты, трогающие общее на процесс, помечены `[Collection(StudioStateCollection.Name)]`. Общего
три: `Localizer` один на процесс, выгрузка контекстов загрузки опирается на сборщик мусора, тоже
один, а регистрация MSBuild, которой служба проектов открывает решения, одна на процесс и
насовсем. Параллельности при этом нет вовсе: `DisableTestParallelization` в `TestApp.cs` (запись
134) — диспетчер Avalonia один на процесс, и параллельный прогон ловил гонку в его пересоздании.
Поэтому время прогона — сумма тестов, и дорогой тест дорог буквально.

Дорогое в тесте — свежая сборка на диске: `TestAssembly.EmitModule`, `EmitFile`, установка примера
из архива. Загрузка нового исполняемого файла — это и проверка антивирусом: 0,4–0,7 секунды, а
иногда ещё около восьми, и один и тот же набор шёл то 4, то 6 минут — отсюда (запись 266). Где
файл не нужен, сборку собирают в память (`TestAssembly.Emit`), а новый тест подъёма не заводят,
если его поведение уже держит соседний.

Имена тестов — английская фраза с подчёркиваниями (`A_pack_made_from_the_template_works`),
сообщения в `Assert` — русские. Проверять надо наблюдаемое поведение, а не внутренние структуры.
`Thread.Sleep` вместо координации не годится: в безголовом режиме время стоит, и у пары жестов
подряд счёт щелчков сбивается — между ними ставят щелчок в стороне, а не паузу.

**Оснастка общая, и новый набор берёт её, а не пишет свою** (запись 286). Службу расширений
собирает `StudioPluginsHarness` — так же, как главное окно, с общим швом сбоев и своим файлом
настроек: `StudioPlugins`, собранная руками без `Settings`, читала бы настоящую папку данных.
Анализатор прогоняет `AnalyzerRun` (`AdditionalFile` — вход сборки), корень репозитория знает
`Repository`, временную папку заводит и убирает `TempFolder`, пример ставит под другим именем
`HelloArchive.Clone`, плагин папкой каталога кладёт `TestAssembly.EmitPlugin`. Окно настроек
открывает `SettingsHarness`, а закрывает его `CloseAsync` — наборы зовут его через `using static`.
Строку состояния подменяют `SilentStatus` и `StatusProbe`, диалоги менеджера — `DialogAnswers`
(`Fakes.cs`). Решение на диске для служб файлов и истории — базовый класс `ProjectsOnDisk`, окно
проекта — `ProjectWindowStudio.OpenedAsync`.

Внутренности студии открыты тестам через `InternalsVisibleTo` в
[ArxisStudio.csproj](src/ArxisStudio/ArxisStudio.csproj).

## Подмодули

Собираются все семь: **Controls** (контролы `Ax*`, lookless), **Icons** (контуры 16×16 и
`AxIcon`), **Themes.Arxis** (палитры, шаблоны, метрики), **Fonts.Cascadia** (шрифт ресурсом),
**Markup** (lossless XAML DOM и round-trip) — все три пакета: синтаксис общий и лежит в `lib/`,
загрузчик везёт служба XAML, — **ProjectSystem** — не весь, а ядро модели, провайдер MSBuild, правку
пакетов и адаптер разметки: первые три держит служба проектов, адаптер — служба XAML, — и
**Surface** — тоже не весь, а ядро холста (`src/Surface`), инструменты (`src/Surface.Editing`) и
дизайнер интерфейса (`src/Surface.UiDesigner`): их везёт модуль дизайнера в своём `bin`, и плагинам они
не общие. Редактор узлов (`Surface.Nodes`) студия не собирает. Библиотека остаётся `net8.0` — это её
наименьшая среда для пакета, а не долг: модуль на `net10.0` грузит её как есть (запись 325). Шрифт
называет не решение, а тема.

**Дизайнер** (`arxis.ui-designer`) — формы `.axaml` решения на холсте Surface, в двух режимах: доска
— все формы карточками на одном холсте, вкладки — каждая открытая форма своей вкладкой. Режим —
настройка `ui-designer.tabs` (по умолчанию вкладки), а решает он одно: кто открывает форму. Модуль отвечает
на вопрос реестра своим редактором документов (`FormEditor`) — модули спрашиваются раньше плагинов, —
и во вкладках берёт форму сам, а на доске отказывается, и файл открывает просмотрщик разметки; вкладка
студии при этом одна на файл. Органы холста — кадр не крупнее ста процентов, «100 %», сетка, цвета —
у доски и у вкладки общие (`SheetControls`). Кисти ядра — ключи `Surface.*` его темы — модуль
подменяет токенами палитры кодом (`CanvasLooks`) плоской записью в ресурсах холста и перекладывает на
смене варианта: свои записи словарь находит раньше тематических (запись 322), и плоская запись без
перекладки дала бы тёмный холст на светлой теме. Размеры карточки — ключи темы `AxFormCard*`, рамки
формы без объявленного размера — `AxFormFrame*`. Длину темы вид, ещё не поставленный в окно, ищет и у
приложения: его дорога вверх кончается на нём самом. У документа, в отличие от панели, нет цели
каретки: студия отдаёт её первому в дереве, кто может взять, — поэтому холст вкладки стоит в разметке
раньше полосы, хотя на экране он под ней. Перехват каретки корнем вида не годится: отданная до
раскладки, она не доставалась никому.

**Вкладка формы живая** (`LiveFormDocument`), когда у студии есть служба XAML, а форма — файл открытого
решения; без службы и вне решения — рамка её размера (`FormDocument`), как прежде. Вкладка открывается
сразу, а документ берёт у службы в фоне: первый документ решения поднимает профиль, сборку и загрузку
типов, и это секунды — чип на полосе говорит, что идёт. На холсте `UiDesignerView` одна карточка —
`UiDesignerFormItem` с корнем показа, приложением формы и его темой: сторону, объявленную
`RequestedThemeVariant` в `App.axaml`, а «по умолчанию» — тему платформы, не студии; без приложения тему
не знает никто, и карточка наследует студийную. Режим карточки **размеченный**: к выбору
предложено то, что документ объявил сам (`GetDeclaredObjects` → `Layout.IsTracked`), — загруженный
спускался бы и во внутренности контролов проекта, построенные их собственной разметкой. Поэтому ввод
форме гасит вкладка: попадание и обход Tab — стилем на `PART_FormHost`, программный фокус — своим
обработчиком на карточке; тема элемента гасит их только загруженному содержимому. Жест холста —
правка текста одним шагом истории документа (`FormGestures`): размер — та сторона, что сменилась, и
туда, откуда его читает дизайнер (`d:DesignWidth`, если он есть); положение — только в `Canvas`;
удаление и перестановка — ответом на просьбы ядра, по якорю, а не по индексу; Ctrl+Z холста и всей
вкладки — история документа. Выбор вкладка помнит путями элементов: правка, замена поколения и отмена
меняют контролы, а не пути, — и ставит его на холст после раскладки (`Reselect`); пропавший путь
уступает родителю, Esc ведёт к родителю. XAML под холстом — `AxCodeView` только для чтения: роли
считаются вне потока интерфейса (`XamlHighlighter`), выбранный элемент отмечен целиком, каретка в
тексте выбирает элемент под собой. Вид — дизайн, XAML или разделение — запоминается настройкой
`ui-designer.view` для следующих вкладок. Вкладка — участник замены: стоп-кадр, отдача выбора, корня и
приложения до показов; и тот, кто одалживает корень (`IXamlRootLender` → `SuspendRoot`). Жест холста
держит замену отсрочкой (`IsInteracting`). Сохраняет она сама (`ui-designer.autoSave`): при уходе из
окна студии, при закрытии и перезапуске (`CanCloseAsync`) и после паузы в правках; вопрос о чужой
записи — баннер с «Взять с диска» и «Оставить мои», и пока он не отвечен, вкладка не пишет: крестик
откладывает ответ, а сохранение отказывает и возвращает вопрос. Остальное, что требует внимания, — один
баннер по важности: форма не открылась, нужен перезапуск, типы не загрузились, чужая Avalonia, документ
закрыт или удалён, текст не показался, сборка упала. Баннер, спрятавшийся вместе с нажатой в нём
кнопкой, отдаёт каретку вкладке.

**Вкладка оставляет снимок формы** для плиток (`LiveFormDocument.Snapshot`): когда форма выглядит иначе —
встал корень, сменилось приложение, текст сохранён или принят с диска, вкладка вернулась в окно, — и
только такой, как на диске: несохранённое, конфликт и стоп-кадр замены не снимаются. Снимается область
`PART_FormBackground` карточки, без рамки и заголовка, на фоне, которым тема приложения формы одевает
окно; тема окна самой студии — не его, и форма без приложения снимается без фона. `RenderTargetBitmap.Render`
рисует элемент в начале холста, а не на его месте в родителе, и поправки «на место» снимку не нужно
(`FormPicture`); спрятанный видом «XAML» холст не снимается — его раскладка прежняя, — а возвращённый
снимается. Хранилище (`FormSnapshots`) кладёт PNG и сведения с отпечатками текста формы и `App.axaml`,
свежесть сверяет по тексту, а поставщик (`FormPreviewProvider`) форм не строит: нет снимка — плитка
остаётся значком.

**Правки строения** — вырезать, копировать, вставить, дублировать, удалить, обернуть, снять обёртку — одной
дорогой у клавиш холста (`SurfaceKeyCommand`) и пунктов его меню (`FormCommands`); пункт выключен там же,
где клавиша не берётся, а сочетания — одна таблица `FormKeys`. Правки идут по путям (`FormEdits`), как и
жесты холста: удаление, перестановка якорем, размер и место — каждая одним шагом истории документа. Буфер обмена — системы,
текстом: фрагменты Markup со своими объявлениями, по порядку документа, — Rider вставит то же, а вставка
берёт и скопированное в нём; несколько элементов подряд читаются внутри корня-обёртки (`FormEdits.Fragments`).
Корень не берётся никуда, вложенное в выбранное не повторяется (`FormEdits.Taken`). Вставка встаёт по правилу
`FormLanding`: в выбранную панель или после выбранного, а несколько — только туда, где мест сколько угодно;
панель ли элемент, отвечает его объект показа (`ObjectAt`). Обёртка и снятие переносят **место в
раскладке**: члены, которыми родитель ставит ребёнка (`Grid.Row`, `Canvas.Left` — присоединённые, чей
владелец — тип родителя или его база: ребёнок наследника сетки ставится `Grid.Row`), уходят с первого
обёрнутого на обёртку и возвращаются детям при снятии. Тип родителя спрашивается у объекта показа, и в
ответ уходят только имена — объект поколения дольше вызова не держится. Снять атрибуты и обернуть одним редактором нельзя — обе правки трогают тот же
элемент, — поэтому текст обёртки собирается в черновике документа, а правка — одна замена на месте первого.
Пути после правки, прибавившей или убравшей соседей, считаются сдвигом (`Shifted`), а не поиском. Меню
(`FormMenu`) холсту отдаёт ядро правой кнопкой (`ContextMenuRequesting`), а клавишей меню и Shift+F10 —
платформа (`ContextRequested`), у выбранного; просьбу платформы на отпускание правой кнопки холст гасит на
пути вниз, иначе поле формы открыло бы своё меню поверх.

**Клавиатура остаётся там, где работает человек.** Выбор из XAML или после правки холст ставит
`SelectTarget(…, takeFocus: false)` ядра: обычный `SelectTarget` берёт клавиатуру, как указатель, и каждый
щелчок в коде уводил её на холст.

Карточку можно **убрать с доски** — меню карточки, Delete или Backspace (запрос удаления ядра доска
выполняет сама): файл формы остаётся, карточка уходит **из коллекции холста**, а не прячется.
Спрятанная осталась бы ячейкой панели, местом в протяжённости и целью рамки выбора и Ctrl+A, и панель
спорила бы с её видимостью — контейнер из пула она включает сама; замер — в записи 329. Уборка — запись
истории холста (`BoardPresence`), отменяется Ctrl+Z, а путь убранной помнится в файле доски списком
`removed`, иначе следующий снимок решения вернул бы карточку. Вернуть — отменой, из меню пустого холста
или кнопкой на доске, где убрано всё. О каждой перемене состава — откуда бы она ни пришла, отменой
тоже — модель сообщает событием (`PresenceChanged`), и строку состояния пишет панель по нему, а не по
пункту меню. Файл доски пишется по одному: ждущая запись подменяется новой, а перемена истории, никого
не сдвинувшая, не пишет ничего. Места карточек — `.arxis/ui-designer/board.json` рядом с решением: точка в
имени папки уводит его от слежения за решением и от локальной истории, и запись доски модель не
перечитывает. Отмена — `SurfaceHistory` ядра; раскладку целиком доска кладёт в неё своим
`ISurfaceChange`.

Доска — **цель тяги студии**: на неё несут формы из окна проекта. Целью объявлена сцена — холст вместе
с надписями состояний, — а не холст: над доской, где убрано всё, курсор стоит над надписью. Пока несут,
в точке курсора стоит заготовка той самой карточки — общим шаблоном, в масштабе холста, заливкой и
кольцом цели перетаскивания, — а надписи состояний на это время прячутся. Формой считается то, что
доска нашла в снимке: разметка приложения, файл вне проекта и каталог не берутся, и подсказка у
курсора говорит почему. Ответ — `Link`, а нет его — `Copy`; перенос доска не берёт. Отпущенное встаёт
одной записью истории (`BoardLanded`): убранное возвращается на прежнее место и уже оттуда едет в
точку броска, стоящее передвигается, — встаёт выбранным, и клавиатура переходит к холсту, чтобы Ctrl+Z
отменил именно бросок.

Слои Surface с тех пор, как сняли дизайнер, ушли вперёд: Surface разделён на слои, вырастил редактор
узлов и элемент формы `UiDesignerFormItem`, а Markup отдал ему заместителя окна — пакета
`Markup.Xaml.Design` в нём больше нет (запись 320). Markup с записи 335 собирается: служба XAML стоит на
нём, — а инструменты и дизайнер Surface с записи 336: на них стоит живая вкладка. Образец дизайнера на трёх семействах разом —
`samples/UiDesigner.Demo` в Surface (запись 323): ему нужны ProjectSystem и Markup рядом. В
`ArxisStudio.slnx` слоёв Surface нет, и работать с ними нужно решением Surface, оно лежит в корне
подмодуля. Так же проверяются Markup, ProjectSystem и ядро Surface: студия собирает их исходники, а их
тесты гоняют их собственные решения.

**API подмодулей можно менять** — это не замороженные зависимости. Если интеграции нужен новый
или изменённый публичный API, правьте прямо в подмодуле и коммитьте в его репозиторий, соблюдая
его правила: у Markup, ProjectSystem и Surface есть свой `CLAUDE.md`, и внутри их каталогов
он старше этого файла. Указатель подмодуля обновляется в том же коммите студии, что и правка,
которой он понадобился.

## Коммиты

Заголовок — русская фраза о том, что стало, без префикса и без точки: «Рейки по краям окна вместо
сворачивания», «Версия сборки закреплена: плагины ссылаются на неё». Тело — проза: что было не
так, почему решено именно так, на что смотрели у Visual Studio и Rider, что уехало в подмодули.
Последняя строка — счёт: `922 теста, 0 предупреждений. Запись 130 в плане.` Запись в
[docs/plan.md](docs/plan.md) идёт тем же коммитом, что и код.
