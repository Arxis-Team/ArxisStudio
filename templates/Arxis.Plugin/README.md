# PLUGIN-NAME

Плагин ArxisStudio. В папке уже есть всё, из чего он состоит: манифест
`plugin.json`, точка входа, команда, кнопка в полосе, панель и словарь.

## Собрать

```
dotnet build
```

Путь к студии плагин берёт из свойства `ArxisStudioPath` — оно объявлено в
`.csproj` и задано при создании. Пока SDK не приезжает пакетом, плагин
собирается против исходников студии; переехали — поправьте свойство или
передайте его сборке:

```
dotnet build -p:ArxisStudioPath=../ArxisStudio
```

## Попробовать в студии

```
dotnet build -p:AxPluginDeploy=true
```

Плагин ляжет прямо в папку студии, мимо менеджера. Закрывать её для этого не
нужно: студия держит не сами файлы плагина, а их теневую копию, — выложите
новую сборку и нажмите «Плагины → Перезагрузить» в меню полосы.

## Отдать другим

```
dotnet build -p:AxPluginPack=true
```

Рядом появится `arxis.my-plugin.axplugin` — его студия ставит через менеджер
плагинов. Это обычный zip: папка с манифестом и `bin/`.

## Что где

| Файл | Зачем |
|---|---|
| `plugin.json` | Всё, что студия показывает, не загружая сборку: команды, меню, полоса, панели |
| `Plugin.cs` | Точка входа и обработчик команды |
| `PluginPanel.cs` | Панель: её место объявляет манифест, класс находится по атрибуту |
| `lang/strings.json` | Строки плагина; `%ключ%` в манифесте берётся отсюда |

## Про строки

Текст, который студия показывает за плагин, — заголовок панели, пункт меню,
подсказка кнопки — пишется ключом `%вот так%` и берётся из `lang/strings.json`.
Ключа нет в словаре — человек увидит `!ключ!`; об этом скажет анализатор при
сборке (`ARX0002`).

Ключ `menu.tools` переведён так же, как в студии, намеренно: ветки меню
сходятся по переведённому тексту, и два плагина, назвавшие ветку каждый своим
ключом, должны оказаться в одном «Команды плагинов», а не в двух одинаковых с
виду.

Перевести плагин на другой язык может кто угодно — языковым пакетом
(`dotnet new arxis-language`), не трогая эту папку.

## Про манифест и код

Манифест и код — две записи об одном, и разойтись они могут молча. При сборке
их сверяет анализатор: `ARX0003` — кнопка зовёт команду, которой плагин не
объявлял; `ARX0004` — свой контрол объявлен, а класса с `[ToolBarItem]` нет;
`ARX0005` — класс помечен атрибутом, а в манифесте о нём не сказано.

## Дальше

- **Полоса.** Кроме кнопки, туда встают выпадающее меню (`"kind": "menu"`) и
  свой контрол (`"kind": "custom"` плюс класс с `[ToolBarItem]`). Значок —
  имя из набора студии (`arxis:Star`) или свой контур в сетке 16×16.
- **Настройки.** Объявите их в `contributions.settings` — студия покажет их на
  экране Settings и отдаст плагину через `Context.Settings`.
- **Фоновая работа.** Всё, что дольше мгновения, — через `Context.Tasks`:
  студия покажет ход и даст отменить, а интерфейс не замёрзнет.
- **Соседи.** `Context.GetService<IStudioExports>()` — обмен реализациями через
  контрактную сборку; `IStudioPlugins` — кто из соседей сейчас поднят.

Полный пример со всем этим — `src/Plugins/Arxis.HelloPlugin` в репозитории
студии. Формат каталога описан в `docs/plan.md`, приложение A.
